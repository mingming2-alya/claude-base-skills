# Round 04｜⛔ 關卡 1a：架構骨架確認單

（資訊部年度成果：事業群年終報告中的資訊部章節，部長上台，總經理與各部門主管都在，約 5 分鐘；章節頁＋3 頁內容）

這一關拍板的是骨架：對誰講、講到哪裡、分幾頁、什麼不講。拍板後才往下寫每頁的內容細節（Step 1b）。骨架做到一半才改最貴，所以請不要只按「確認」：下面的最弱的一點和最沒把握的假設，請你判斷（Q1、Q2），四個最貴的決定請逐項勾（Q3）。

## 先給你看：骨架確認單

### 1. 目標、聽眾與場合
- **理性終點（部長定）**：總經理聽完相信「資訊部今年從後勤變成引擎」，再支持明年資料平台擴大到全事業群的預算。
- **體感預期（我的草案）**：燈亮時總經理心裡冒出「我年初那句話，他們真的接住了；資料平台可以讓他們擴大。」
- **主受眾**：總經理，最在意這些工作對事業群有什麼用（你的話）；可能的疑問：「引擎」是不是說過頭、擴大值不值得、擴大後撐不撐得住。
- **次受眾**：事業群各部門主管，包括提客製需求的部門 → 不排名、不點名，用「我們」的語氣，不怪需求部門。他們也是資料平台擴大後的使用者。
- **年度成果的標竿缺口怎麼補**：當初承諾 vs 實際 → 用總經理年初那句話當考題（年初稿沒有目標值，不事後補目標）；突破與取捨 → AI 客服、資料平台，主線只講「集中力氣」；能不能擴大 → 資料平台擴大到全事業群；還沒解決的問題 → 客製開發刻意不進主線，部長小抄備答；明年 → 擴大＋預算（金額年終報告前會有）。
- **場合**：日常匯報（briefing）、部長上台、亮室投影、會後寄出或存檔（每頁要能自己讀懂）。
- **硬限制與決策人**：事業群模板（章節頁標題固定「資訊部」＋最多 3 頁）；課長先看、部長定稿；部長問卷 5 題已全部回覆。

### 2. 不講的範圍（已確認）與尚未確定的事
- **不講**：①客製開發：不上頁面，部長小抄備答（只講「人力優先給了 AI 客服與資料平台」「部分報表需求改用資料平台自己查」，不提需求部門；小抄不放進會寄出的檔案）；②帳號管理；③年初的工作項目清單（系統維運只留結果數字）。
- **尚未確定（都不影響骨架）**：①預算金額：年終報告前會有，第 3 頁先留金額欄；②事業群模板檔：收到後確認版面；③數字口徑：99.95% 的計算期間、1,800 小時的估算方式、2.1 萬次是單月或月平均（1b 查核）；④部長小抄裡剩下 8 項需求明年怎麼處理（1b 問課長或部長）；⑤年終報告日期（決定數字截止日，問課長）。

### 3. 故事種子、母題與選定的架構
- **故事種子 ⭐**：部長選的那句：「總經理年初說過『今年資訊部要從後勤變成引擎』，我一直記著這句話。」你確認了是年初事業群會議上公開說的，所以可以直接引用。
- **承重母題**：「從後勤變成引擎」：章節頁開場當考題、第 1 頁交答案、第 3 頁結尾回扣到明年。
- **選定的架構：你改寫的混搭版**：考題回扣版的開場與結尾回扣，三頁改成「答案 → 價值 → 基座與請求」。
- **和三個候選比**（完整的同一把尺比較在 round-03 第 4 段）：保留考題回扣版的三個優點（第 1 頁就回答「有什麼用、做到了沒」、照部長的先後先相信再談預算、時間順序不排名）；你把維運移到最後當底氣，解掉了它第 1 頁維運和引擎擠在一起的問題；維運也不再像年初三塊版那樣用第 1 頁講後勤。

### 4. 30 秒口述邏輯鏈
「總經理年初在事業群會議上說，今年資訊部要從後勤變成引擎〔起點〕。但是後勤只要系統不出事，引擎得直接替業務帶來價值〔但是〕。所以今年我們把力氣集中在兩件能帶動業務的事：AI 客服每年約省 1,800 小時人工回覆，資料平台 3 個部門每月查詢 2.1 萬次〔所以＋證據〕。而後勤的底線也守住了，全年資安事件 0 件、可用率 99.95%，這是明年擴大的底氣〔證據〕。因此請總經理支持明年把資料平台擴大到全事業群；明年年底，我們希望報告的是整個事業群的引擎〔因此〕。」
→ 我唸過：每句都接得上前一句，沒有平行條列。唯一會卡的是「這是明年擴大的底氣」這一跳，見下方最弱的一點。

### 5. 停靠點、分鐘數與頁數

| 頁 | 頁題 | 分鐘 | 這頁唯一要記住的事 |
|---|---|---|---|
| 章節頁 | 資訊部（固定） | 0.5 | 部長說出總經理年初在事業群會議上的那句話：今年的考題 |
| 1 | 從後勤到引擎 | 1 | 考題的答案：兩件事開始直接帶動業務，後勤的底線也守住 |
| 2 | 引擎帶來的價值 | 1.5 | AI 客服每年約省 1,800 小時（估算）；資料平台 3 個部門每月查詢 2.1 萬次 |
| 3 | 基座與明年擴大 | 2 | 底線穩（資安 0 件、可用率 99.95%）是底氣；請總經理支持資料平台擴大到全事業群；結尾回扣 |
| 合計 | 4 頁（上限 4） | 5 | |

我在你的版本上調了兩處，不同意可以在 Q4 的「其他」退回：
- **配分不平均**：第 1 頁只交答案，1 分就夠；第 3 頁同時扛底氣和要總經理決定的事，給 2 分，請求才不會講得太趕。
- **第 3 頁頁題**：從「基座撐得住擴大」改成「基座與明年擴大」。頁題只寫這頁在講什麼，「撐得住」這個結論放內文；而且「撐得住」正是下面最弱的那一點，還沒補實前更不適合放在標題。

### 6. 結構追問的結果
- **第 1 頁 從後勤到引擎**：拿掉會斷：章節頁的考題沒有答案，第 2 頁的數字變成沒有標準的成績單。這頁做了別頁沒做的：給總態勢，並用一句白話分清後勤和引擎（後勤是系統不出事，引擎是直接替業務帶來價值）。要注意：只放結論、兩件事的名字和底線一句，數字細節留給第 2、3 頁，免得和第 2 頁重複。
- **第 2 頁 引擎帶來的價值**：拿掉會斷：答案沒有證據，「引擎」變成口號。這頁做了第 1 頁沒做的：用數字證明，並換成總經理有感的單位（1b 定口徑）。
- **第 3 頁 基座與明年擴大**：拿掉會斷：請求沒地方放，部長要的預算支持沒人扛，維運成果也不見。這頁做了第 2 頁沒做的：從今年轉到明年，用底線當底氣，提出請求。要注意：請求要是這頁的重點，不能縮在頁尾。
- **開場承諾在哪兌現**：章節頁拋出總經理的考題 → 第 1 頁交答案 → 第 3 頁結尾把考題延伸到明年。

### 7. 改起來最貴的四個決定（與理由）
1. **理性終點**：先相信「從後勤變成引擎」，再支持預算。理由：部長在問卷第 1、3 題親口定的，先後也是部長給的。
2. **主受眾**：總經理；各部門主管是次受眾。理由：總經理拍板預算，也是那句話的出處；各部門主管在場，所以不排名、不怪需求部門。
3. **軸與敘事主幹**：時間順序「年初的考題 → 今年的答案與價值 → 明年擴大」，開場與結尾回扣總經理那句話。理由：年初稿沒有目標值，總經理的話是唯一說得出口的承諾；時間順序中性；維運放最後，請求才有底氣。
4. **範圍**：主線只講 AI 客服、資料平台、系統維運與明年擴大。理由：部長同意拿掉客製開發；3 頁上限；提需求的部門主管在場。

### 8. 最弱的一點與最沒把握的假設
- **最弱的一點（Q1）**：第 3 頁用「資安事件 0 件、可用率 99.95%」當擴大的底氣，但這兩個數字量的是今年的規模（資料平台只上線 3 個部門），而且量的是整個資訊環境、不是資料平台本身。「今年穩」推不出「擴大到全事業群也撐得住」，總經理或在場主管可能就追問這一點。
- **最沒把握的假設（Q2）**：總經理和各部門主管會接受用兩個早期成果撐「從後勤變成引擎」：1,800 小時是客服組估算的年化值，資料平台只上線 3 個部門。
- 上一輪的最沒把握的假設（那句話能不能公開引用）你已經確認：是年初事業群會議上公開說的，這項已排除。

## 表單

### Q1｜第 3 頁的推論缺口
資訊部年終報告這一章的第 3 頁「基座與明年擴大」，用今年的資安事件 0 件、機房可用率 99.95% 當「明年資料平台擴大到全事業群」的底氣。但這兩個數字量的是今年的規模（資料平台只上線 3 個部門），而且是整個資訊環境、不是資料平台本身；總經理或在場主管可能追問「擴大到全事業群還撐得住嗎？」這個缺口要怎麼補？可複選。
- 複選
- A. 第 3 頁補一句「擴大需要的容量與人力就在這筆預算裡」（推薦）：理由：預算的範圍與方向已經確定、金額年終報告前會有，補這一句就把「今年穩」和「明年撐得住」接起來；不必動頁序，也守住你「維運放最後當底氣」的設計。
- B. 補資料平台本身的穩定紀錄：例如今年資料平台有沒有停機或事故（要你向維運同仁確認）
- C. 不補：頁面維持「今年穩 → 請支持」，被追問時由部長口頭說明擴大的規劃

### Q2｜「引擎」說法的分寸
部長最希望總經理記住「資訊部今年從後勤變成引擎」。但撐這句話的兩個成果還在早期：AI 客服的 1,800 小時是客服組估算的年化值，資料平台只上線 3 個部門。總經理和各部門主管都在場，頁面上寫「已經變成引擎」可能被覺得說過頭。頁面上的說法要怎麼處理？
- 單選
- A. 1b 把說法校準、請部長點頭（推薦）：考題和答案方向不變，頁面寫成「引擎發動了」這類有分寸的版本，數字標明「估算」「3 個部門」。理由：說法有分寸就不怕追問，還能順勢接到第 3 頁：引擎剛發動，擴大到全事業群才會真的帶動整個事業群。
- B. 照部長原話「從後勤變成引擎」，不校準：總經理自己的話，原汁原味最有力；被追問時由部長口頭補數字的邊界。
- C. 不確定：請課長或部長決定

### Q3｜四個決定說得清嗎
資訊部年終報告這份骨架有四個「改起來最貴」的決定：做到一半才改，就要回到這一關重來。請勾出你已經能向課長和部長說清楚理由的；沒勾的，我們先處理再往下做。（各項理由在上方第 7 段）
- 複選
- A. 理性終點與體感預期：總經理先相信「資訊部今年從後勤變成引擎」，再支持明年資料平台擴大的預算；燈亮時心裡冒出「我年初那句話，他們真的接住了；資料平台可以讓他們擴大。」
- B. 主受眾：總經理（拍板預算、也是那句話的出處）；各部門主管是次受眾，所以不排名、不怪需求部門
- C. 軸與敘事主幹：時間順序「年初的考題 → 今年的答案與價值 → 明年擴大」，開場與結尾回扣總經理那句話
- D. 範圍：主線只講 AI 客服、資料平台、系統維運與明年擴大；客製開發與帳號管理不進主線（客製開發備部長小抄）

### Q4｜骨架拍板
資訊部年終報告這一章，照這份骨架（章節頁＋3 頁：從後勤到引擎 → 引擎帶來的價值 → 基座與明年擴大；配分 0.5／1／1.5／2 分）拍板，進入下一步逐頁內容細節（Step 1b）嗎？課長先看、部長定稿，所以也請決定骨架什麼時候給課長看。要改頁序、配分或頁題，請在「其他」寫。
- 單選
- A. 拍板，同時把這份骨架給課長過目（推薦）：理由：課長是第一個審稿人、能否決結構；骨架只有 4 個頁題和一段 30 秒口述，現在給課長看幾乎不花時間，對齊最便宜；我照常往下做 1b，課長若只調頁題或配分，改起來很便宜。
- B. 拍板，1b 做完再一起給課長看：少一次往返，但課長若要改頁序，1b 寫好的內容要重做
- C. 先等課長看過骨架再拍板：最穩，但要多等一輪
