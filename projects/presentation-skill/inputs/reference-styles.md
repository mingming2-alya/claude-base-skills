## 二、最強參考「AI 的第三次搬家」的技術解剖

### 關鍵事實：它是「整頁背景圖 + 獨立文字層」，不是文字畫在圖裡

量測證據：

| 檢查 | 結果 |
|---|---|
| `pdfimages -list` | 每頁 1 張 1672×941 的 JPEG，**覆蓋率 100.0%** |
| `pdfplumber` 抽文字 | 每頁都有**完整可抽取的文字層**（69–238 字） |
| 文字與圖片關係 | 圖片是整頁底圖，文字浮在其上 |

**這非常重要**：文字是真文字，不是畫在圖裡。所以「文字可編輯、可搜尋、可重用」——與我們 `deck.html` 的「HTML 文字疊在 CSS 背景上」是**同一個架構**。這是可以重現的，不是 codex-ppt-skill 那種文字畫死在圖裡的不可編輯路線。

### 四層結構（實測）

**① 背景層** — 柔和漸層 + 左右漫射光暈，沒有硬邊界：

| 頁 | 平均色相 | 平均飽和 | 平均明度 | 主要色 |
|---|---|---|---|---|
| p1 | 77.6° | 0.37 | 0.68 | `#F0D8D8`(29%) `#F0F0D8`(7%) |
| p2 | 58.4° | 0.37 | 0.77 | `#F0F0D8`(37%) |
| p3 | 47.0° | 0.43 | 0.69 | `#F0D8D8`(32%) |
| p4 | 98.6° | 0.32 | 0.68 | `#F0D8D8`(12%) `#F0D8C0`(10%) |
| p5 | 56.1° | 0.31 | 0.78 | `#F0F0D8`(29%) |

色彩特徵：**低飽和（0.31–0.43）、高明度（0.68–0.78）、色相集中在 46–99°（暖黃橘綠）**。粉彩紙感，不是純色底也不是深色底。

**② 圖像層** — 邊緣的黏土質感 3D 物件（紙箱、工具箱、書桌、顯示卡、機器人、積木）＋中央右側的產品截圖。物件**貼齊畫面邊緣裁切**，中央文字區完全留空。

**③ 元素層** — 圓潤的圓角矩形、柔和的雙層陰影、細的連接線、色塊卡片。

**④ 文字層** — 繁體中文、深灰墨色（非純黑）、左對齊、字重對比明顯。頂部有「事業群 A」章標，底部有**五步導航點**（AI 為什麼要搬家？／新家需要多大空間？／AI 怎麼搬進新家？／新室友能幫什麼忙？／搬到桌面，還需要雲端嗎？）。

### 「融入」的技術核心（可歸納成可檢查的規則）

1. **共用一個光源**：所有黏土物件的陰影方向一致（左上打光，右下投影）。
2. **共用一套色調**：物件的顏色取自背景的同一個色相家族（暖黃橘綠），沒有跳色。
3. **物件貼邊、中央留空**：裝飾永遠在版面外圈，文字區是乾淨的。
4. **文字用深灰不純黑**（`#303030` 級），與柔和的背景不打架。
5. **陰影柔和無硬邊**：與背景的漫射光暈同一種質感。
6. **物件有敘事**：紙箱、書桌、顯示卡都對應「搬家」這個主題——**裝飾不是隨機的，它說故事**。

第 6 點是最關鍵也最容易被忽略的：**物件與內容主題對應**，所以「融入」不只是視覺的，也是語意的。

## 三、其他參考的共同特徵

| 參考 | 風格 | 我們的清單有嗎 |
|---|---|---|
| 微信圖片 ×3 | 資訊圖表型：長條圖、圓餅圖、色塊卡片、大量留白 | ❌ 缺（我們只有 `table` 與 `stats`，沒有真正的圖表版型） |

| NotebookLM clay / brick | 紙黏土定格動畫、積木組合 | ❌ 缺（屬插畫型，需圖像生成） |

## 四、對我們的診斷的意義

1. **「不夠活」的答案已經在使用者的參考裡**：內圈留空 + 外圈黏土物件 + 漫射光暈 + 共用光源與色調。這是可以只用 CSS + 圖像做到的（不必整套 3D）。
2. **它驗證了「圖像層提前到風格規格」的決定**：這份簡報的「融入」**就是**圖像層與背景層一起設計的結果。分兩步選（先排版再風格）不可能做出來。
3. **它跨越了我們現有的分類**：色彩上（低飽和粉彩、暖黃橘綠、高明度）在我們的 10 個風格裡沒有任何一個接近——`washi` 最接近但飽和度與質感都不同。**這是新的調性群集。**
4. **它示範了「允許裝飾與文字交錯」的安全做法**：App 5 的物件貼邊、中央留空——裝飾與文字**不重疊但視覺上是一體的**。這比「圈字、螢光筆」更值得先學，因為它同時滿足了「活」與可讀性。

## 五、Apple Design skill（已查證）

`github.com/emilkowalski/skills`，路徑 `skills/apple-design/`，**MIT 授權**，可以借用並標註來源。

內容是把 WWDC 的《Designing Fluid Interfaces》翻譯成 web 做法：用 spring 取代 easing curve、pointer capture 做 1:1 跟手、放手時接手速度並預測慣性、核心原則是 **interruptibility**（動畫可以在半途被抓住並反向，不必等它跑完）。

**這是我們缺的一整塊**：現有 `runtime.js` 是固定長度的進場動畫（expo-out 0.9s），沒有「可打斷」的概念。`gsap-*` 技能也在 repo 裡（全 8 個），可以做，但專案規則要求**引入 GSAP 前先問使用者並說明為什麼 CSS 做不到**。
