## 五、各案重點

### 案一：處長人才峰會開場

- **做得好**：
  - Round 0 刻意不先端出自己的診斷，先聽使用者的講法。
  - 辨識出「期許／動員演講＋活動開場」，v4.10 新增的那一列有用到。
  - 抓出人數缺口：主管約 40 位、潛力工程師約 80 位，「每位主管認領 1 位」會讓一半的人覺得被挑剩，違背「不是被考核」。
  - 給處長的 3 題問卷還沒回，關卡 1a 先備好退路：用今天下午的導師配對當承諾。
- **待改**：推薦破框版，要把處長的故事拆成三幕。使用者選回自己的版本，但吸收了 Agent 點出的三個弱點：開場提問沒回答、故事直接掉進數字、現況太薄。最後的骨架比 v1 正確架構多了「最後回答開場提問」。

### 案二：AI 報表助理推廣

- **做得好**：
  - Round 0 用一題複選問齊誰上台、會後寄不寄、6 頁含不含封面、誰能改結構。
  - 不編節省工時數據；排程自動寄送只講一句。
  - 推薦的前提（多數人知道舊版難裝）放在同一張表單問。使用者答「只有少數廠知道」後，Agent 立刻承認推薦不成立，回到使用者版本。
- **待改**：推薦用的那把尺（裝過舊版的廠會先問什麼）是從「有些廠反感」推出來的，前提還沒驗證就先推薦。Agent 另回報兩個工具問題，見發現 4、5。

### 案三：資訊部年度成果

- **做得好**：
  - Round 0 就問到事業群模板與頁數、誰上台與拍板。
  - 做了 5 題部長問卷，回覆後理性終點用部長原話。
  - 關卡 1a 點出使用者版本第 3 頁的推論缺口：今年系統穩，不代表擴大到全事業群也撐得住。
  - 頁題自動照「只寫這頁在講什麼」改。
  - 客製開發改做部長小抄，不放進會寄出的檔案。
- **待改**：Round 0 先給了結構診斷（年初三塊是並列清單），才問心中的講法，可能錨定使用者。

### 案四：雙週進度會

- **做得好**：
  - 快速模式也先問心中的改法並收碎片。
  - 讀模板發現「三段順序固定」，把使用者想改順序的版本列為架構 B 比較，推薦「模板不動、只改寫法」。
  - 範圍主動加一頁給各單位的填寫規範。
  - 核對日期是星期幾，例如 12/5 是週六。
- **待改**：沒問總覽能有幾頁，提了 2 頁，被使用者糾正「只能一頁」，關卡 1a 重送一次。快速模式沒有固定的架構硬限制題。

## 六、發現與建議修補

1. **推薦偏向 Agent 的版本**（中）：
   - 現象：標準模式三案推薦的都不是使用者版本。其中案一、案二使用者版本才是已知正確；案三推薦的版本接近正確。這次使用者有反駁才沒走偏；被動的使用者會拿到 Agent 的計畫，正是防被動同意要擋的情況。
   - 第一組也一樣：案一、案二的 Agent 推薦別的版本，使用者看到最弱的一點後反駁，才回到自己的版本。第一組把它記成「防被動同意有效」；兩組合計 4 次，都要靠使用者反駁。
   - 建議：推薦不是使用者版本時，
     - 同一題附「你的版本＋補掉最弱點」選項（案二有，案一沒有）；
     - 寫出使用者版本比推薦好在哪；
     - 推薦依據的前提還沒驗證，就先問前提，或把推薦寫成條件句（「如果……就推薦……」）。
2. **快速模式沒有固定問架構硬限制**（低，v4.10.1 已處理主因）：案四的 agent 送關卡時說「5 題額度只剩 1 題」，「≤5 題」上限是漏問的主因之一；v4.10.1 已刪除上限，並寫明「沒把模板、硬限制與必守邊界問清絕不停下」。仍建議兩種模式的 Round 0 都放一題複選事實題，問誰上台、誰拍板、頁數上限（含不含封面與目錄）、指定模板或章節、會後寄不寄，讓硬限制在第一輪就問到。案二 Round 0 第 4 題可當範本。
3. **Round 0 先給診斷會錨定**（低）：建議 Round 0 只呈現查到的事實，例如數字核對、讀了哪些檔。結構診斷與意見等使用者說完心中的講法再給，照案一的做法。第一組報告把案一、案三「一讀完就點出病根」記為優點，可見技能沒寫清楚診斷該在什麼時候給。
4. **lint 欄位比對漏抓**（低，程式錯誤）：`**欄位名**（說明）：` 這種寫法會被判成找不到欄位。建議放寬比對規則，允許欄位名後面接括號說明。
5. **目錄頁不能手動指定**（低）：
   - 現象：目錄頁由章數自動決定，3 章以內不插，4 章以上插一頁議程或每章一頁。使用者明確要或不要目錄時做不到。
   - 為什麼要修：目錄頁占頁數上限，屬於架構硬限制。
   - 建議：storyboard 加 `meta.toc`（`auto`／`none`／`agenda`／`per-chapter`）覆寫自動判斷，頁數算術跟著算。
6. **輪數**（觀察）：標準模式到關卡 1a 要 4–5 輪、16–19 題，10 分鐘的簡報也一樣；第一組是 5 輪、15 題。題目沒有灌水，每張都問滿 4 題；照使用者「第一步最重要」的優先順序，建議維持。

## 七、這次驗證的限制

- 扮演使用者的是寫這套技能的 Claude，知道正確答案。為了降低帶風向，答案在開跑前寫好、只答被問到的，但無法完全排除。
- 已知正確架構來自 v1 時期和使用者一起定的版本。這次驗的是技能能不能**引導出**使用者腦中的架構與限制，不是能不能從零想出正確架構。
- 只跑到關卡 1a；1b 之後的內容深挖、逐頁清單與視覺，要靠真實簡報 PK 驗證。
