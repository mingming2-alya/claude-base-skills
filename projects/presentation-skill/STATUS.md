## 使用者偏好與規則

- **所有問題一律用互動表單問**（`CLAUDE.md` 規則三）。看完圖之後的審閱，使用者習慣自由回饋；決策題才用表單。
- **總結永遠不當主標題**：主標題只寫題目，是頁面上最大的字；總結只出現在內文，關鍵字可以用強調色。檢查方式：畫面上最大、最先被看到的字，是不是這頁的題目。
- **重點只用顏色標示**，不畫底線。用無彩色當焦點時，內文改灰、關鍵字用墨色。
- **版面上下的限制**：頁面上下除了章節頁籤不放其他文字。
- **引言**用英文引號。
- **裝飾可以和文字交錯**，可讀性由驗證把關：WCAG 對比要過，文字不能溢出。
- **底色與漸層**：底色不用純白或純黑；不用紫色主調的漸層（OKLCH 色相 280–335）。
- **用色**：鎖規則、不鎖色碼，不放品牌色；全部風格都要淺、深兩種底。
- **插畫場景**：背景與元素要融在一起，不要左文右圖、不要把場景框成一幅畫。
- **生圖**：只在需要時列清單，由使用者生圖。程式先畫，畫不出水準再列需求。
- **檔案保密**：含公司內部資訊的簡報檔不上傳，只記抽象結論。
- **排版**：相鄰兩頁不用同一種排版，但同一類內容要用同一種。
- **內容與版面**：內容結構由敘事決定；每種風格都要有多個有來源的排法。

## 製作與驗證的眉角

- **畫圖方式**：意象圖都是 1920×1080 的 HTML、CSS、SVG，用 Playwright 的 Chromium 截成 JPG。Chromium 要走 session 的 proxy 才載得到 Google Fonts：`chromium.launch({ proxy: { server: process.env.HTTPS_PROXY } })`。
- **`render.cjs`**：`outputs/illustration-integration/`、`outputs/illustration-renderings/`、`outputs/color-modes/` 各有一支。`node render.cjs [檔名片段]` 會產生 JPG 並檢查：
  - 文字框不超出畫面、不溢出。
  - 字體都載入成功。
  - 頁面腳本沒有錯誤。
  - **每段文字對它背後實際畫出來的東西**符合 WCAG 對比。做法是把文字藏起來截圖，取字形範圍的第 10 與第 90 百分位亮度。
  - 不帶參數時，另外重建該資料夾的 `sheet*.jpg` 或 `overview.jpg`。
- **漸層字不在 `render.cjs` 的檢查範圍**：Apple 的關鍵字與產品名是漸層填色，由 `outputs/color-modes/make.py` 逐段檢查。
- **這次踩過的坑**：
  - 全域變數不要叫 `top`，會和 `window.top` 衝突，整段腳本不執行。
  - SVG 的 id 不能重複。clipPath 與群組同名時，畫到的會是 clipPath。
  - 用 Python 組 HTML 時，記得補 `</script>`。
  - 佔位字串不要出現兩次，否則程式會被代換兩份。
  - 畫面邊緣有暗角時，那裡的文字容易對比不足。
- **工作節奏**：每畫完一張就 commit、push，因為 worker 可能重啟。
- **檢查圖面**：先縮成 960×540 再看，省篇幅；細節再裁局部看原尺寸。
