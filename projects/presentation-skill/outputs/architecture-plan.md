# deck-architect 架構規劃（定案版，2026-11-10）

> 規劃的演變過程見 `../LOG.md`。這份是最後整合的版本，v0 依此實作。

## 定位

> 架構決定一切：先幫你想清楚怎麼帶聽眾走，再讓畫面替架構說話。
> 給經常做各種簡報的人：一次 Grill，自動適應場景，越用越懂你。

## 五個設計原則

1. 架構先於設計：先找出聽眾的起點和終點，畫面最後才決定。
2. 簡單勝過說明：不寫過場文字，用結構本身導航。
3. 使用者做決定、AI 執行：只在三個時刻參與（Grill、三選一樣張、成品留言）。
4. 規則交給機器：能檢查的寫成腳本，不能檢查的不寫。
5. 先穩再炫：每項進階功能都有退路。

## 核心模型：架構

- **起點**（聽眾現在知道／在意什麼）→ **終點**（聽完要相信／做什麼）。
- **軸**：起點和終點差在哪個維度。時間、流程、因果、抽象層次、重要性、尺度、距離、強度；分「價值軸」與「中性軸」。
- **方向**：從起點那端出發，單一方向。
- **停靠點**：章節，2–4 個，用這次內容自己的話命名，用詞平行。
- **選軸**：依目的；有人際顧慮時選中性軸。
- **兩個層次**：架構層永遠是路徑（目錄導航）；內容層可並列但要有排序依據（頁籤導航）。

## 八條鐵律

1. 先有架構再寫內容：最上層章節在同一條軸上。
2. 目錄、頁籤只在一處定義。
3. 標題只說這頁在講什麼。
4. 一般重點放在內容裡，放大加突出色，一頁最多一處。
5. 不寫過場文字：>3 章用目錄點亮，單章 >2 頁用頁籤。
6. 震撼頁只給情緒轉折或刻意衝擊，要有鋪陳、全場 0–2 次、不連續。
7. 震撼頁打破所有規則：導航隱藏、畫面淨空、停頓後進場。
8. 把圖拿掉，文字依然讀得懂。

視覺分工：導航（在哪裡，一致安靜）／一般重點（記住什麼，每頁一處）／震撼頁（有感覺，打破前兩層）。

## 情境適配

- 5 個維度：目的、播放情境、信任來自、受眾關係、製作節奏。類型只是維度的常見組合。
- 製作模式：快速（週會，沿用風格、不做樣張）／標準／旗艦（分層生圖、動態預覽、影片）。
- 旋鈕可依章節調整，整份簡報設上限。

## 流程

1. ● Grill → brief.md（起點、終點、人際顧慮、2–3 個架構候選、各章重點、震撼的一刻）
2. ○ 架構展開 → storyboard.yaml（lint 把關）
3. ◐ 架構摘要（可跳過）
4. ● 三選一樣張（封面＋一般內容頁＋震撼頁）
5. ○ 製作 → deck.html
6. ○ 品管（check 腳本＋獨立評審，最多修 2 輪）
7. ● 交付與留言修改
8. ○ 記憶

## 視覺系統

- 由軸推導鏡頭與導航：時間／因果／流程 → 水平；重要性／抽象層次 → 垂直；尺度／距離 → 縮放、同心圓。
- 導航本身就是貫穿全片的物件。
- 三級退路：分層生圖＋視差＋前景遮擋文字（旗艦）→ 整張無字插畫＋動態背景（標準）→ 純程式背景（快速）。
- 單一 HTML 核心；PPTX 從 HTML 匯出（背景、插畫元素、原生文字方塊三層）；Codex 風格整張圖交給 codex-ppt-skill。

## 開發路線

| 版本 | 內容 | 完成條件 |
|---|---|---|
| v0 ✅ | 流程骨架、lint、HTML 簡報、三種主題、樣張、check | 能跑通全流程 |
| v1 架構核心 | 依真實使用修 Grill 與架構推導；可編輯 PPTX；快速模式 | 3 份不同類型的真實簡報，推薦的架構和使用者直覺一致 |
| v2 品質與記憶 | 獨立評審、品味記憶、儲存風格、依軸的導航動畫、成品留言修改 | 評審抓到的問題使用者大多同意；同類簡報明顯變快 |
| v0.5 實驗（可與 v1 平行） | 分層生圖＋前景遮擋文字 | 達到成功標準，否則旗艦改用第 2 級 |
| v3 旗艦 | 分層生圖、主角物件、影片匯出、codex-ppt 串接 | 活動開場類達到「Codex 質感＋會動」 |

預估：4 個大版本、約 10–15 次小迭代；每次迭代都需要一份真實簡報當測試材料。

## 已知缺點與緩解

1. 太複雜 → SKILL.md 精簡、規則交給腳本、分版本上線。
2. 技術風險（分層生圖）→ 先實驗、三級退路、單一渲染核心。
3. 依賴 AI 品味 → 關鍵判斷留給使用者、獨立評審、內容與引擎分離、PPTX 文字可編輯。
