# 情境判斷、主題類型總表、三段式舞台光譜與製作模式

同一套流程要能處理 10 分鐘週會，也能撐起 30 分鐘年度旗艦峰會。差別不在流程，而在兩個輸入：**主題類型**（決定標竿必答維度與推薦風格）與**場合**（`stage_mode`，決定要挖多深、呈現要校準到什麼程度）。

---

## 一、三段式舞台光譜（`stage_mode`）

**誰在什麼時候決定什麼**：
- **Gate 1a 只拍板 `stage_mode`**，並把播放方式（`delivery`）與播放環境（亮室會議室／暗場大螢幕／線上分享／列印或寄送）記進 `brief.md`。
- 下表的明暗、去框比例與導航是主柱二的**校準基線**：在 **Gate 2a／2b 選定與定版風格時**，依「`stage_mode` × 風格 DNA × 播放環境」一起寫進 `storyboard.yaml`。

| 設計開關 | `briefing`（週報／決策會議／進度檢核） | `pitch`（商業提案／深度匯報／培訓） | `keynote`（產品發表／年度峰會／大會開場） |
|---|---|---|---|
| **核心任務** | 快速對齊事實、卡點與決策 | 建立信任、講清因果機制、促成拍板 | 創造記憶峰值、情感共鳴與發表會體感 |
| **明暗極性策略（Gate 2 校準）** | **`single` 單一主調鎖定**（多偏亮底 ≥75% 溫潤紙面，高速掃讀零跳動） | **`accent-invert` 局部反轉**（主調為主，原話見證／關鍵轉折切反差） | **`bipolar` 光暗雙極呼吸節奏**（`dark / light / split / photo` 交錯，禁連 >5 頁同質色） |
| **框線與卡片比例（Gate 2 校準）** | **高紀律結構化卡片／表**（Bento 儀表板、甘特、狀態表） | **半去框化／畫廊細線分區**（`zones ≤ 4` 溫白紙卡或細線，避免層層套框） | **高去框化編輯（≥40–50% 無圓角框）**（白棚裸數、細線清單、35/65 分割、物象軌跡） |
| **導航殼層 `nav_mode`（Gate 2 校準）** | `top-bar`（頂部章節列＋頁籤） | `top-bar` 精簡版或高密頁 `minimal-side` | `divider-only`（章節大扉頁定位＋系列頁極簡側錨；底控自動隱藏） |
| **節拍與步進控制** | 預設 **`0-step` 從容慢板自動展開**（高密 `talk`/`discuss` 推導頁仍可開 `data-step`） | **`talk`/`discuss` 單頁 ≥3 依序推導區塊即開 `data-step`（≤5 拍）防破梗**；其餘 `0-step` | **從容慢板自動指引 ＋ `data-step` 雙軌**（多層換幕、公式補完、金句停頓） |
| **實物、影音與活 Demo** | 比例圖表、收斂漏斗與必要實證為主 | 1–2 處產品實景、互動試算或活流程示範 | 實物剖面＋照片牆＋原話暗房＋外連影音／音檔＋HTML5 活流程輪播 |
| **敘事與藏牌（Gate 1a 決定）** | 透明單軸、結論與機制清晰、零藏牌 | 單軸＋故事轉折點＋選用承重母題 | 單軸＋**承重母題**＋可選 `unlisted` **One More Thing 驚喜幕** |

> **原則**：不要把商務週報硬做成暗黑霓虹後台，也不要讓高階戰術提案退化成塞滿小字的死板方框。

## 二、主題類型總表（唯一來源）

這張表是 Gate 1a 標竿盲點掃描與 Gate 1b／2a 推薦 3 套比稿風格共同引用的**唯一來源**。核心邏輯：**標竿必答維度＝這類聽眾在做決定之前，一定會先問的問題**。

| 主題類型 | 標竿必答維度 | 常見盲點（顧問要追問） | 常見場合 | Gate 2a 推薦比稿風格組合（優先序） |
|---|---|---|---|---|
| **週報、進度回報、例會決策** | 一句話總態勢（綠 vs 紅）→ 唯一卡點與根因 → 2 個可拍板選項（含代價）→ 需要誰、何時支援 | 資訊平攤讓主管自己找問題；紅燈只報現象，沒給可拍板的選項 | `briefing`（`discuss`） | `workday`、`counsel`、`apple (light)` |
| **商業或策略提案、資源申請、高階戰術匯報** | 不做的代價／收斂邏輯 → 方案與分工機制 → 實證成果與 ROI → 風險邊界 → 明確請求／閉環 | 只羅列工作清單卻看不出收斂因果，或把口頭解釋塞滿畫布 | `pitch`／`briefing`（`talk`／`discuss`） | `counsel`、`workday`、`apple` |
| **年度成果、專案結案** | 當初承諾 vs 實際成果 → 關鍵突破與背後取捨 → 可複製的能力沉澱 → 還沒解決的真問題 → 下一階段閉環 | 淪為流水帳報 KPI，漏掉「為什麼做得到」與「明年怎麼接」 | 例會 `briefing`／`pitch`；峰會 `keynote` | 例會：`counsel`、`workday`、`apple`；峰會：`apple`、`illustration`、`counsel` |
| **團隊或組織成長回顧** | 一年前的樣子 → 關鍵轉折與選擇 → 能力或制度的前後證據 → 人的故事 → 下一階段支持 | 變成活動流水帳；沒有前後對照證據；沒有點名人 | `pitch`／`keynote` | `illustration`、`apple`、`workday` |
| **技術架構評審、事件覆盤** | 問題邊界與約束 → 候選設計取捨（為何不選 B）→ 壓測或實測證據 → 失效模式與降級預案 → 負責人 | 只放最終架構圖，沒講為什麼不選替代方案、最壞情況怎麼保底 | `briefing`／`pitch` | `counsel`、`workday`、`apple` |
| **產品或技術發表** | 使用者有感的痛點瞬間 → 一句話核心突破 → 現場實證與真實邊界 → 立即上手路徑 | 沉迷底層術語，沒先讓聽眾對痛點有感，也沒說清適用邊界 | `pitch`／`keynote`（`talk`） | `apple`、`counsel`、`illustration` |
| **知識分享、教學工作坊、新人引導** | 學習者的舊觀念誤區 → 1 個核心新框架 → 正反案例或實作演練（`job: scaffold`）→ 帶得走的步驟清單 | 知識點塞太多、平鋪直敘，沒有正反對照或可照做的演練卡 | `pitch`（`talk`） | `illustration`、`workday`、`apple` |
| **期許、動員演講** | 為什麼是現在與你們 → 共同看見的現實（不究責）→ 具體行為期許 → 支持承諾 → 帶得走的行動 | 變成訓話檢討；有人際顧慮卻用「你們」；幫主管做沒先發問卷 | `keynote`／`pitch`（`talk`） | `apple`、`illustration`、`counsel` |
| **活動開場、慶典** | 為什麼今天聚在這裡 → 共同記憶或成就 → 流程與期待 → 一個情緒高點 | 冗長致詞與流程宣讀，沒有情緒峰值 | `keynote`（`talk`／`auto`） | `apple`、`illustration`、`counsel` |

## 三、五個情境維度與特殊來源處理

| 維度 | 選項 | 影響 |
|---|---|---|
| 目的 | 告知 / 說服 / 啟發 / 促成決策 / 慶祝 | 主題類型、架構軸線、`stage_mode`、震撼頁次數 |
| 播放情境（`delivery`） | `talk` 上台講 / `discuss` 討論 / `read` 自己讀 / `auto` 自動播放 | 每頁字數基準、`data-step` 啟用時機、講者備註 |
| 信任來自 | 數據 / 實物與實證 / 故事與原話 / 氛圍 | 逐頁 `slide_plan.visual_encoding` 與資產需求 |
| 受眾關係 | 內部 / 外部客戶 / 跨部門／公開觀眾 | Grounding 深度、人際中性軸、正式程度 |
| 製作節奏 | 一次性 / 定期更新 / 一套多版本 | 是否沿用既有模板（多人進度回報讀 `progress-report.md`） |

- **計畫轉成果三步**：① 動作語言換成價值與改變語言 → ② 從主受眾最在意的視角重排順序 → ③ 沒成果的區塊果斷移入 `Out of Scope`，關鍵實證數字拉回主線附出處。

## 四、兩種製作模式（皆強制遵守透明導覽與同意才過關）

### 標準模式（預設 · 透明 5 道關卡）
**Round 0（5 關路線圖＋硬限制）→ ⛔ Gate 1a（破框架構骨架）→ ⛔ Gate 1b（去重 `brief.md`＋逐頁 `slide_plan`＋文字預確認 3 個風格方向）→ ⛔ Gate 2a（關鍵 1 頁 3 子代理並行活體比稿＋混搭建議）→ ⛔ Gate 2b（合成 `deck.css`＋定版活範本 1 輪確認沒走鐘）→ ⛔ Gate 3（100% 子代理精雕＋分鏡條＋單輪 Critic → HTML 與 PDF 交付）**。

### 快速模式（例行週會、使用者明說趕時間）
- Round 0 硬限制照問（頁數、模板與決策人絕不盲猜），合併於 **⛔ Gate 1b** 一次確認精簡 `brief.md`（標註「快速」）與 `storyboard.yaml` 逐頁清單。
- **跳過 Gate 2a/2b 與 Critic**：沿用使用者偏好或〈主題類型總表〉首選風格，直接派乾淨 Builder 子代理產出 `deck.html` 與品管報告於 **⛔ Gate 3** 交付。
