# 情境判斷、三段式舞台光譜與製作模式

同一套流程要能處理 10 分鐘週會，也能撐起 30 分鐘年度旗艦峰會。差別不在流程，而在**舞台光譜（`stage_mode`）的開關力度**——由場合與體感預期動態決定，絕不一刀切。

---

## 一、三段式舞台光譜（`stage_mode`，視場合動態決定視覺語法）

在 Step 1 Grill 確認目的、對象、場合與體感預期後，拍板以下三種舞台層級之一，作為整份簡報的視覺與互動總開關（寫入 `brief.md` 的 Stage Spec）：

| 設計開關 | `briefing`（週報／決策會議／進度檢核） | `pitch`（商業提案／深度分享／培訓） | `keynote`（產品發表／年度峰會／大會開場） |
|---|---|---|---|
| **核心任務** | 快速對齊事實、卡點與決策 | 建立信任、轉變觀點、促成合作 | 創造記憶峰值、情感共鳴與發表會體感 |
| **明暗極性策略** | **`single` 單一主調鎖定**（多偏亮底，高速掃讀零視覺跳動） | **`accent-invert` 局部反轉**（主調為主，原話見證／震撼轉折切暗或亮反差） | **`bipolar` 光暗雙極呼吸節奏**（`dark / light / split / photo` 交錯，禁連 >5 頁同質色） |
| **框線與卡片比例** | **高紀律結構化卡片／表**（Bento 儀表板、甘特、狀態表） | **半去框化**（核心主張與實物去框，數據對比保留輕分區） | **高去框化編輯（≥40–50% 無圓角框）**（白棚裸數、細線清單、35/65 分割、物象軌跡） |
| **導航殼層（`nav_mode`）** | `top-bar`（頂部章節列＋頁籤，隨時精準定位） | `top-bar` 精簡版或系列頁 `minimal-side` | `divider-only`（暗場章節大扉頁定位＋系列頁極簡側邊錨點；正文零頂部雙層橫條、底控自動隱藏） |
| **節拍與點擊控制** | **100% 自動視覺指引**（一鍵翻頁 `0-step`） | 以自動為主，關鍵 1–2 頁可選 `data-step` | **自動指引 ＋ 講者點擊步進（`data-step`）雙軌**（多層換幕、公式補完、金句停頓） |
| **實物、影音與活 Demo** | 數據圖表與必要截圖為主，零多餘影音 | 1–2 處產品實景、互動試算或輕量活流程示範 | 實物剖面／爆炸圖＋照片牆＋原話暗房＋外連影音／實測音檔＋HTML5 活流程輪播 |
| **敘事與藏牌** | 透明單軸、結論先行、零藏牌 | 單軸＋故事轉折點＋選用承重母題 | 單軸＋**承重母題**＋可選「先體驗後數據」／`unlisted` **One More Thing 驚喜幕**／3-2-1 收斂 |

> **原則**：不要把商務週報硬做成電影發表會，也不要把年度峰會做成 20 頁暗色監控後台。`stage_mode` 是建議基線，使用者在 Grill 中隨時可針對單一開關（例如 `pitch` 也想開啟完整光暗雙極）做客製調整。

## 二、五個情境維度（輔助判斷 `stage_mode` 與版型）

| 維度 | 選項 | 影響 |
|---|---|---|
| 目的 | 告知 / 說服 / 啟發 / 促成決策 / 慶祝 | 架構軸線、`stage_mode`、震撼頁次數 |
| 播放情境（`delivery`） | `talk` 上台講 / `discuss` 討論 / `read` 自己讀 / `auto` 自動播放 | 每頁字數上限、原則 #26 嚴格度、講者備註 |
| 信任來自 | 數據 / 實物與實證 / 故事與原話 / 氛圍 | 逐章說服載體（Proof Medium）與資產需求 |
| 受眾關係 | 內部 / 外部客戶 / 跨部門／公開觀眾 | Grounding 深度、人際中性軸、正式程度 |
| 製作節奏 | 一次性 / 定期更新 / 一套多版本 | 是否沿用既有模板、風格與結構 |

常見組合速查（僅作起點，不當硬框架）：

| 常見類型 | 典型 `stage_mode` | 震撼頁 | 每頁密度 |
|---|---|---|---|
| 會議決策／週報 | `briefing`（`discuss`・數據） | 0 | 中高 |
| 客戶洽談／商業提案 | `pitch`（`talk`/`discuss`・實證＋故事） | 0–1 | 中 |
| 年度成果（部門例會） | `briefing` 或 `pitch`（`talk`・數據＋案例） | 0–1 | 中 |
| 年度峰會／產品發表 | `keynote`（`talk`・實物＋故事＋氛圍） | 1–2（含可選驚喜幕） | 低 |
| 新知科普／經驗分享 | `pitch`（`talk`・故事＋活示範） | 1–2 | 低 |
| 活動開場 | `keynote`（`talk`/`auto`・氛圍＋影音） | 2 | 極低 |

> `delivery: read`（對方自己讀）沒有講者口頭補充，每頁保留完整閱讀脈絡，講者備註可省略。

## 三、特殊來源處理

### 定期進度回報
結構由模板固定、多人填寫且每期更新，改讀 `progress-report.md`：先讀空白模板 → 給填寫規範 → `check_reports.py` 檢核 → 總覽用 `status-table` 或 `workday` Bento。

### 計畫轉成果（年度成果、結案報告）
直接把年初計畫填上進度通常會失焦。改寫必守三步：
1. **換成成果語言**：從「做了什麼動作」改為「創造了什麼價值與改變」。
2. **依聽眾重排順序**：計畫常由底層往上排；成果報告從聽眾最在意的視角或已著陸的體驗出發。
3. **敢刪**：沒有實質成果或不屬這條路徑的區塊整塊移除；關鍵數字從附件拉回主線並附出處。

若前一版最上層是並列工作類型，於 Grill B 階段標註風險並提供路徑化候選（詳見 `structure.md`）。

## 四、兩種製作模式

### 標準模式（預設）
完整走完三關卡（Grill 設計樹前沿清空確認 `brief.md` → Gate 2 視覺關卡選風格、明暗策略與配色 → 成品交付修改）。
- **固定規則**：無論哪一種 `stage_mode`，只要進入標準模式，Step 1 Grill 提架構候選時**全面必給至少 1 個跳脫思維的破框候選**（`DESIGN-IT-TWICE`），幫講者打開想像空間，最後由講者自行選擇穩健、破框或混搭。

### 快速模式（週會、臨時會議、使用者明說趕時間）
- Grill 壓縮至 1–2 輪（≤5 題）：鎖定起點／終點、`stage_mode`（預設 `briefing`）、`delivery`、時長與頁數算術、既有框架與 `constraints`，提 1–2 個務實架構（可略過破框候選）。
- 跳過 Gate 2 三選一樣張：沿用上次偏好的 Style DNA；無紀錄時依情境選一款（會議數據 `counsel`/`workday` 淺色、產品發表 `apple`、分享宣導 `illustration`），交付時告知可切換風格或極性。
- 起點、終點、單軸架構、頁數算術與 `constraints` 地雷**任何模式皆不可省略**。
