# 呈現規則：標題、重點、導航、震撼頁與品管

整份簡報的視覺分工只有三層，每一層做一件事：

```text
導航（依 stage_mode：頂列／側錨／大扉頁）→ 告訴聽眾「在哪裡」   → 單一資料來源、不搶主視覺
一般重點（放大・突出色）                   → 告訴聽眾「記住什麼」 → 每頁最多一處
震撼頁（獨立・淨空・停頓）                 → 讓聽眾「有感覺」     → 全場 0–2 次，打破上面兩層
```

前兩層建立的秩序越穩定，第三層打破時就越有力。**震撼來自對比，對比需要先有秩序與光暗落差。**

## 1. 主標題與總結（鐵律）

- **總結永遠不當主標題**：主標題只寫「這頁在講什麼」（路標，≤12 字、不帶句號或結論語氣），且**必須是這頁最大、最先被看到的字**（`check.mjs` 自動檢查主標題字級 ≥ 總結字級）。
- **總結放在主標題下方的內文**：用突出色標出關鍵詞（`==重點==`），字級約為主標題的一半左右，不搶過主標題。
- 自我檢查：**「這頁打開三秒內，最先映入眼簾的最大字，是不是這頁的題目？」**

## 2. 一般重點、原則 #26 去小字（含合法豁免）與去框紀律

- **原則 #26｜畫面上只留視覺錨點，講者稿歸講者稿**：
  - 在 `delivery: talk` 模式下，**每個一般視覺群組／卡片／標註最多 2 層文字**（例如「大數字＋6 字內短標」、「時間膠囊＋6 字動作標」、「方案名＋一句結果」）。
  - 所有口頭補充、背景脈絡與修辭說明一律放進 `notes`（講者備註），畫布保持清爽三秒掃讀。
  - **四類明確合法豁免（與 AI 冗餘廢話小字切開）**：
    1. **原始證言暗房（Verbatim Quote）**：客戶、使用者或決策者的真實逐字原話，語氣與細節本身就是最高公信力證據，允許獨立成主視覺區塊完整呈現。
    2. **產品發表級情感短句**：在 `keynote` 實物特寫頁，允許精練品牌短標與單句情感副文與高精細實物共構。
    3. **實機／活流程操作步進提示**：HTML5 活流程示範或互動試算器中的極簡步驟微標。
    4. **教學演練／正反範例與工作清單（`slide_plan.job: scaffold`）**：工作坊、Prompt／程式碼正反對照或帶得走的 SOP 清單，允許保留學習者實作必讀的完整語句（`lint.py` 自動放寬字數上限）。
- **依場合決定去框與否（Anti-Card-itis）**：`briefing` 以高紀律卡片／表為主；`pitch` 半去框或溫白畫廊分區；`keynote` 至少 40–50% 內容頁採**無圓角卡片框版面**。
- **重點只用顏色標示**（不畫底線、不用斜體）；每頁最多一處 `==重點==`。支援單一主焦點色＋可選第二語意主色（如機制色 × 成果色），亮底維持 ≥75% 溫潤中性紙面。
- **允許裝飾與文字交錯，可讀性由像素 WCAG 把關**：界線是 `check.mjs` 真實像素對比通過（≥24px 或 ≥18.66px 粗體達 `3:1`，其餘 `4.5:1`）且無溢出。
- **頁面上下保持乾淨**：除該 `stage_mode` 對應的導航、極小頁碼與資料來源，不放重複簡報名稱、標語或冗餘頁眉頁腳。
- **引言用英文引號** “ ”，不用「」。
- **底色與漸層禁忌**：不用純白（`#FFFFFF`）或純黑（`#000000`）；不用紫色主調漸層（OKLCH 色相 280–335）；全部風格支援淺、深兩種底，且**變暗不等於夜晚**。
- **大字與步驟斷行**：大字加 `data-fit="phrase"`（標點後斷行、必要時縮至 72%）；大數字群組加 `data-fit-group="figure"`＋`data-fit="figure"`；`steps` 的 `detail` 用 `\n` 指定斷行。

## 3. 導航（依 `stage_mode` 分級，單一資料來源，不寫過場）

| 導航模式（`nav_mode`） | 對應 `stage_mode` | 呈現方式 |
|---|---|---|
| **`top-bar`** | `briefing`（預設） | 頂部單一資料來源章節列；單章 >2 頁顯示頁籤；>3 章自動目錄點亮頁（每章平均 <2 頁則只在封面後插一頁總目錄） |
| **`minimal-side`** | `pitch` ／ 高密單頁或系列頁 | 正文不堆雙層頂部橫條，改以超輕量側邊或局部進度錨點同步位置 |
| **`divider-only`** | `keynote`（預設） | 以全出血章節大扉頁承擔定位，正文內容頁 100% 淨空；底部控制列自動隱藏 |

- 封面、結尾、震撼頁與 `unlisted: true` 的驚喜幕皆隱藏常駐導航。
- **不寫過場文字**（「接下來我們來看…」「了解背景後…」）。

## 4. 震撼頁（`type: shock`）

只留給**情緒轉折**或**刻意衝擊**（如 One More Thing）：
- 必須有鋪陳（唯一例外：`role: opener` 開場提問，放封面後第一頁）。
- 全場 0–2 次，兩次之間至少隔 3 頁；文字極短（≤20 字）。

## 5. 一頁總覽、附件頁與防濫用指引

- **一頁總覽（`layout: pillars`＋`meta.format: section`）**：將整條架構濃縮在一頁，每章一欄；不需封面與頁碼。
- **可點入的附件（`appendix: true`＋`id`＋`link`）**：不在線性翻頁順序內，點入後可按返回鈕或 `Esc` 回原頁。
- **附件正當用途與防濫用**：補充口徑、明細長表與 `limitations` 鼓勵放進 `notes` 或 `appendix` 以保持主頁清爽；但不可把主線核心結論藏進附件來規避頁數上限。

## 6. 可信度、人際顧慮與繁體中文在地化

- **數字與圖表必附 `source`（或於 `notes` 註明完整口徑）**：先跟原始資料核對出處、加總與適用範圍（已實現 vs 預期目標嚴格區隔）。
- **限制與地雷入檔檢查**：`limitations`、`forbidden`、`must_include` 寫進 `storyboard.yaml` 的 `constraints`；補充口徑寫在 `notes` 或 `appendix` 即通過 `lint.py`，不強迫塞入主頁畫布。
- **有人際顧慮（`sensitivity: true`）**：批評改寫成以「我們」開頭的反思提問，不出現「你們」。
- **繁體中文台灣習慣用語在地化**（`meta.lang: zh-Hant` 時 `lint.py` 自動偵測簡體字）：使用「檔案」「簡報」「專案」「品質」「軟體／硬體」「伺服器」「預設」「影片」。

## 7. 節奏、密度與頁數算術

- **頁數算術**：`封面 + 自動目錄 + 內容 + 震撼 + 結尾 = 總頁數`（不含附件），可用 `meta.toc` 明確覆寫目錄模式。
- **每頁字數基準（`lint.py` 軟性提醒供單輪 Critic 語意複核，不設死硬阻斷）**：
  - `talk`：~110 字（≥2 分/頁 ~148 字；≤1 分/頁 ~93 字）；若與 `slide_plan.anchors` 差距過大，由 Critic 判斷是否可圖解化。
  - `discuss`：~150 字；`read`：~240 字；`auto`：~60 字（`status-table`、`lanes`、`pillars`、`table`、`quote`、`code-stage`、`scaffold` 豁免）。

## 8. 視覺工藝基準與收尾邊界

1. **真實無字實物與 AI 融合底圖優先**：具生圖工具或真實資產時，優先採無字 16:9 底圖融 HTML 真文字層（反左右割裂構圖）；無圖時包進 `.asset-slot[data-slot]` 並附 `IMAGE_UPGRADE.md`。
2. **乾淨收尾在 HTML 與 PDF**：交付物為 100% 離線互動 `deck.html` 與列印級 `deck.pdf`；若使用者需可編輯 PPTX，引導開啟新對話將 `deck.html` 轉為可編輯原生 PPTX，絕不以截圖拼湊假 PPTX。
