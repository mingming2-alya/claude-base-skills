# 呈現規則：標題、重點、導航、震撼頁與品管

整份簡報的視覺分工只有三層，每一層做一件事：

```
導航（章節列・目錄・頁籤）→ 告訴聽眾「在哪裡」   → 單一資料來源、一致安靜
一般重點（放大・突出色）  → 告訴聽眾「記住什麼」 → 每頁最多一處
震撼頁（獨立・淨空・停頓）→ 讓聽眾「有感覺」     → 全場 0–2 次，打破上面兩層
```

前兩層建立的秩序越穩定，第三層打破時就越有力。**震撼來自對比，對比需要先有秩序。**

## 1. 主標題與總結（鐵律）

- **總結永遠不當主標題**：主標題只寫「這頁在講什麼」（路標，≤12 字、不帶句號或結論語氣），且**必須是這頁最大、最先被看到的字**（`check.mjs` 會自動檢查主標題字級 ≥ 總結字級）。
- **總結放在主標題下方的內文**：用突出色標出關鍵詞（`==重點==`），字級約為主標題的一半左右，絕不搶過主標題。
- 自我檢查：**「這頁打開三秒內，最先映入眼簾的最大字，是不是這頁的題目？」**

## 2. 一般重點與排版偏好

- **重點只用顏色標示**，不畫底線、不用斜體；每頁最多一處 `==重點==`。無彩色焦點（墨黑／紙白）時，總結內文改說明灰、關鍵字用墨黑／紙白。
- **允許裝飾與文字交錯，可讀性由像素 WCAG 把關**：不再死板禁止裝飾與文字互動（例如內生題箋、浪花切角、適度交疊），界線是 `check.mjs` 真實像素對比必須通過（≥24px 或 ≥18.66px 粗體達 `3:1`，其餘 `4.5:1`）且文字不得溢出。
- **頁面上下保持乾淨**：除了章節導航／頁籤、極小頁碼與資料來源，不放重複的簡報名稱、標語或冗餘頁眉頁腳。
- **引言用英文引號** “ ”，不用「」。
- **底色與漸層禁忌**：不用純白（`#FFFFFF`）或純黑（`#000000`）；不用紫色主調漸層（OKLCH 色相 280–335）；全部風格支援淺、深兩種底，且**變暗不等於夜晚**。
- **大字與步驟斷行**：大字加上 `data-fit="phrase"`（標點後才斷行、放不下自動縮字至 72%）；大數字群組加 `data-fit-group="figure"`＋`data-fit="figure"`；`steps` 的 `detail` 可用 `\n` 指定精準斷行位置。

## 3. 導航（由輕底盤自動同步，不寫過場）

| 情況 | 底盤自動處理 |
|---|---|
| 一般內容頁 | 單一資料來源章節列（風格可自訂 `#nav` 樣式，或於自由畫布放 `<nav class="slide-nav" data-auto-nav></nav>` 由 `assemble.py` 填入章節並自動隱藏全域 `#nav`） |
| 章節數 > 3 且每章平均 ≥ 2 頁 | 每章開始前自動插入**目錄點亮頁** |
| 章節數 > 3 但每章平均 < 2 頁 | 只在封面後插入**一頁總目錄**，避免目錄頁比內容多 |
| 單章內容頁 > 2 | 自動顯示該章頁籤 |
| 封面、結尾、震撼頁 | 自動隱藏導航 |

**不寫過場文字**（「接下來我們來看…」「了解背景後…」）。需要寫過場代表架構不夠清楚。

## 4. 震撼頁（`type: shock`）

只留給**情緒轉折**或**刻意衝擊**（如 One more thing）：
- 必須有鋪陳（唯一例外：`role: opener` 開場提問，放封面後第一頁，鋪陳來自聽眾經驗）。
- 全場 0–2 次（會議簡報常為 0 次），兩次之間至少隔 3 頁。
- 文字極短（≤20 字），可加一行小副句；底盤自動隱藏導航、先切全黑停頓再浮現。

## 5. 一頁總覽、附件頁與防濫用指引

- **一頁總覽（`layout: pillars`＋`meta.format: section`）**：將整條架構濃縮在一頁，每章一欄，垂直軸預設逐階高低錯落；不需封面與頁碼。
- **可點入的附件（`appendix: true`＋`id`＋`link`）**：不在線性翻頁順序內，點入後可按返回鈕、Esc 或方向鍵回原頁。
- **附件防濫用指引**：附件頁只給「現場被追問才點開的補充細節」（原始數據長表、方法論細項、備查案例），**不可把主線應該講完的內容塞進附件來規避頁數上限**。附件頁數過多時（>3 頁或超過主線一半），`lint.py` 會警告。

## 6. 可信度、人際顧慮與繁體中文在地化

- **數字與圖表必附 `source`**：大數字、多數字、圖表與含數字的震撼頁皆須先跟原始資料核對並寫明出處與適用範圍。
- **限制與地雷入檔檢查**：brief 的限制／不承諾、禁用說法、必放項目要寫進 `storyboard.yaml` 的 `constraints`，交給 `lint.py` 把關。
- **有人際顧慮（`sensitivity: true`）**：批評改寫成以「我們」開頭的反思提問，不出現「你們」；數據框成「系統卡在哪」，不點名究責。
- **來源為簡體中文時的轉換與在地化**（`meta.lang: zh-Hant` 時 `lint.py` 會自動偵測簡體字）：
  - 不只轉字形，同時改為台灣習慣用語：例「檔案」（非文件）、「簡報」（非演示文稿）、「專案」（非項目）、「品質」（非質量）、「軟體／硬體」（非軟件／硬件）、「伺服器」（非服務器）、「預設」（非默認）、「影片」（非視頻）、「數據／資料」（視語境）、「改善／調整」（減少過度使用「優化」）。

## 7. 節奏、密度與頁數算術

- **頁數算術**：`封面 + 自動目錄 + 內容 + 震撼 + 結尾 = 總頁數`（不含附件），在 brief 階段即確認含不含封面與目錄。
- **每頁字數依 `meta.delivery` 動態調整**（`lint.py` 自動套用）：
  - `talk`（上台講）：預設 ~110 字；每頁講 ≥2 分鐘放寬至 ~148 字，節奏快（≤1 分/頁）收緊至 ~93 字。
  - `discuss`（會議討論）：~150 字（`status-table`、`lanes`、`pillars`、`table` 豁免）。
  - `read`（對方自己讀）：~240 字，可保留完整閱讀脈絡。
  - `auto`（自動播放／開場）：~60 字。

## 8. 圖像層：零等待程式版＋可選 `IMAGE_UPGRADE.md`

- 自由畫布中的複雜插畫或攝影場景，預設先由程式一次畫出完整可看版，同時用 `<div class="asset-slot" data-slot="..." data-mode="...">...</div><!-- /slot -->` 包住背景／場景層。
- 隨簡報附上可選的 `IMAGE_UPGRADE.md`（構圖留白區、OKLCH 配色與無字提示詞），使用者有空或需要旗艦質感時把圖放到 `assets/` 重跑 `assemble.py` 即可無縫升級。

## 9. 品管清單（Step 5 親自看截圖逐條檢查）

1. 只看章節名稱，能否一眼說出從哪裡帶到哪裡？
2. 每一頁最大、最先看到的字是不是「題目」而非「總結」？
3. 每一頁三秒內能否找到唯一重點？有沒有不該出現突出色的地方？
4. 實測像素對比、漸層字對比、溢出、最小字級與 SVG ID 是否全部通過 `check.mjs`？
5. 大字與一般內文有沒有醜斷行（斷在詞中間或孤字成行）？
6. 相鄰兩頁構圖有沒有變化（`series` 除外）？整體是否維持同一套 Style DNA？
7. 震撼頁前有鋪陳、外觀明顯打破秩序嗎？
8. brief 的地雷、限制與必放項目是否全部落實？
