# 呈現規則：標題、重點、導航、震撼頁與品管

整份簡報的視覺分工只有三層，每一層做一件事：

```text
導航（依 stage_mode：頂列／側錨／大扉頁）→ 告訴聽眾「在哪裡」   → 單一資料來源、不搶主視覺
一般重點（放大・突出色）                   → 告訴聽眾「記住什麼」 → 每頁最多一處
震撼頁（獨立・淨空・停頓）                 → 讓聽眾「有感覺」     → 全場 0–2 次，打破上面兩層
```

前兩層建立的秩序越穩定，第三層打破時就越有力。**震撼來自對比，對比需要先有秩序與光暗落差。**

## 1. 主標題與總結（鐵律）

- **總結永遠不當主標題**：主標題只寫「這頁在講什麼」（路標，≤12 字、不帶句號或結論語氣），且**必須是這頁最大、最先被看到的字**（`check.mjs` 自動檢查主標題字級 ≥ 總結字級）。
- **總結放在主標題下方的內文**：用突出色標出關鍵詞（`==重點==`），字級約為主標題的一半左右，不搶過主標題。
- 自我檢查：**「這頁打開三秒內，最先映入眼簾的最大字，是不是這頁的題目？」**

## 2. 一般重點、原則 #26 去小字（含合法豁免）與去框紀律

- **原則 #26｜畫面上只留視覺錨點，講者稿歸講者稿**：
  - 在 `delivery: talk` 模式下，**每個一般視覺群組／卡片／標註最多 2 層文字**（例如「大數字＋6 字內短標」、「時間膠囊＋6 字動作標」、「方案名＋一句結果」）。
  - 所有口頭補充、背景脈絡與修辭說明一律放進 `notes`（講者備註），畫布保持清爽三秒掃讀。
  - **三類明確合法豁免（與 AI 冗餘廢話小字切開）**：
    1. **原始證言暗房（Verbatim Quote）**：客戶、使用者或決策者的真實逐字原話，語氣與細節本身就是最高公信力證據，允許獨立成主視覺區塊完整呈現（不硬縮成一句無感摘要）。
    2. **產品發表級情感短句**：在 `keynote` 實物特寫頁，允許精練品牌短標與單句情感副文與高精細實物共構（如 1–2 行產品文案）。
    3. **實機／活流程操作步進提示**：HTML5 活流程示範或互動試算器中的極簡步驟微標（讓聽眾跟上當前操作狀態）。
- **依場合決定去框與否（Anti-Card-itis）**：`briefing` 以高紀律卡片／表為主以利快速掃讀；`pitch` 半去框化；`keynote` 至少 40–50% 內容頁採**無圓角卡片框版面**（白棚裸數、細線清單、35/65 分割錨點、自然物象軌跡、原話暗房），避免全場淪為後台 UI。
- **重點只用顏色標示**（不畫底線、不用斜體）；每頁最多一處 `==重點==`。無彩色焦點（墨黑／紙白）時，總結內文改說明灰、關鍵字用墨黑／紙白。
- **允許裝飾與文字交錯，可讀性由像素 WCAG 把關**：界線是 `check.mjs` 真實像素對比通過（≥24px 或 ≥18.66px 粗體達 `3:1`，其餘 `4.5:1`）且無溢出。
- **頁面上下保持乾淨**：除該 `stage_mode` 對應的導航、極小頁碼與資料來源，不放重複簡報名稱、標語或冗餘頁眉頁腳。
- **引言用英文引號** “ ”，不用「」。
- **底色與漸層禁忌**：不用純白（`#FFFFFF`）或純黑（`#000000`）；不用紫色主調漸層（OKLCH 色相 280–335）；全部風格支援淺、深兩種底，且**變暗不等於夜晚**。
- **大字與步驟斷行**：大字加 `data-fit="phrase"`（標點後斷行、必要時縮至 72%）；大數字群組加 `data-fit-group="figure"`＋`data-fit="figure"`；`steps` 的 `detail` 用 `\n` 指定斷行。

## 3. 導航（依 `stage_mode` 分級，單一資料來源，不寫過場）

| 導航模式（`nav_mode`） | 對應 `stage_mode` | 呈現方式 |
|---|---|---|
| **`top-bar`** | `briefing`（預設） | 頂部單一資料來源章節列；單章 >2 頁顯示頁籤；>3 章自動目錄點亮頁（每章平均 <2 頁則只在封面後插一頁總目錄） |
| **`minimal-side`** | `pitch` ／ 連續三部曲系列頁 | 正文不堆雙層頂部橫條，改以超輕量左側或局部進度錨點（如 `做深／做廣／做新`、`01/02/03`）同步位置 |
| **`divider-only`** | `keynote`（預設） | 以全出血暗場章節大扉頁承擔大方向定位，正文內容頁 100% 淨空（僅系列頁附局部側邊錨點）；底部播放控制列自動隱藏 |

- 封面、結尾、震撼頁與 `unlisted: true` 的驚喜幕皆隱藏常駐導航。
- **不寫過場文字**（「接下來我們來看…」「了解背景後…」）。需要寫過場代表架構或大扉頁定位不夠清楚。

## 4. 震撼頁（`type: shock`）

只留給**情緒轉折**或**刻意衝擊**（如 One More Thing）：
- 必須有鋪陳（唯一例外：`role: opener` 開場提問，放封面後第一頁，鋪陳來自聽眾經驗）。
- 全場 0–2 次（會議簡報常為 0 次），兩次之間至少隔 3 頁；在 `keynote` 雙極節奏中，前頁亮棚後切暗場更能放大「突然關燈」的戲劇對比。
- 文字極短（≤20 字），可加一行小副句或三組簡潔佐證數據；底盤自動隱藏導航、先切暗幕停頓再浮現。

## 5. 一頁總覽、附件頁與防濫用指引

- **一頁總覽（`layout: pillars`＋`meta.format: section`）**：將整條架構濃縮在一頁，每章一欄，垂直軸預設逐階高低錯落；不需封面與頁碼。
- **可點入的附件（`appendix: true`＋`id`＋`link`）**：不在線性翻頁順序內，點入後可按返回鈕、Esc 或方向鍵回原頁。
- **附件防濫用指引**：附件只放現場被追問才點開的補充細節（原始長表、口徑明細、備查案例），**不可把主線應該講完的內容塞進附件來規避頁數上限**。附件過多時（>3 頁或超過主線一半），`lint.py` 會警告。

## 6. 可信度、人際顧慮與繁體中文在地化

- **數字與圖表必附 `source`**：大數字、多數字、圖表與含數字的震撼頁皆須先跟原始資料核對並寫明出處、口徑與適用範圍（已實現 vs 預期目標嚴格區隔）。
- **限制與地雷入檔檢查**：brief 的限制／不承諾、禁用說法、必放項目寫進 `storyboard.yaml` 的 `constraints`，由 `lint.py` 把關。
- **有人際顧慮（`sensitivity: true`）**：批評改寫成以「我們」開頭的反思提問，不出現「你們」；數據框成「系統卡在哪」，不點名究責。
- **來源為簡體中文時的轉換與在地化**（`meta.lang: zh-Hant` 時 `lint.py` 自動偵測簡體字）：同步轉為台灣習慣用語（例「檔案」「簡報」「專案」「品質」「軟體／硬體」「伺服器」「預設」「影片」「改善／調整」）。

## 7. 節奏、密度與頁數算術

- **頁數算術**：`封面 + 自動目錄 + 內容 + 震撼 + 結尾 = 總頁數`（不含附件），在 brief 階段即確認含不含封面與目錄。
- **每頁字數依 `meta.delivery` 動態調整**（`lint.py` 自動套用）：
  - `talk`（上台講）：預設 ~110 字；每頁講 ≥2 分鐘放寬至 ~148 字，節奏快（≤1 分/頁）收緊至 ~93 字。
  - `discuss`（會議討論）：~150 字（`status-table`、`lanes`、`pillars`、`table` 豁免）。
  - `read`（對方自己讀）：~240 字，保留完整閱讀脈絡。
  - `auto`（自動播放／開場）：~60 字。

## 8. 視覺工藝基準與圖像／媒體層

1. **真實無字實物與 AI 融合底圖優先**：硬體剖面、插畫場景與電影感封面若具生圖工具或真實資產，優先採用實物照／無字 16:9 底圖與 HTML 真文字層融合（生圖嚴守反左右割裂構圖，見 `templates/image-upgrade.md`），拒絕以簡陋幾何色塊假裝實物或手繪；無圖時先給程式版並將場景包進 `.asset-slot[data-slot]`、附 `IMAGE_UPGRADE.md`。
2. **依場合選對視覺載體（Proof Medium）**：商務進度與決策採 `workday` 現代 Bento（左行動主軸→右健康總覽）；旗艦發表與產品頁採白棚無框剖面、羽化融圖 Bento、35/65 分割錨點、物象軌跡構圖、原話暗房或無框光學信號燈。
3. **數據故事化與活 Demo**：與其堆乾數字表，改用單位矩陣、比例色塊、現場試算滑桿（`.live-ctrl`）或 HTML5 原生活產品流程輪播；真實影片與實證音檔採外連媒體掛載。

## 9. 品管清單（Step 5 親自看截圖逐條檢查）

1. 只看章節／大扉頁名稱，能否一眼說出從哪裡帶到哪裡？Grounding 順序是否順暢？
2. 每一頁最大、最先看到的字是不是「題目」而非「總結」？標題與下方內容和諧一致嗎？
3. **場合契合度（`stage_mode`）**：明暗極性節奏、去框化比例、承重母題連貫性與導航輕重，是否兌現 `brief.md` 的 Stage Spec？
4. **原則 #26 檢核**：一般視覺群組是否維持 ≤2 層文字、口白歸還 `notes`（合法豁免之原話暗房與產品情感主標除外）？
5. 每一頁三秒內能否找到唯一重點？有無不該出現突出色的地方？
6. 實測像素對比、漸層字對比、溢出、最小字級與 SVG ID 是否全部通過 `check.mjs`（及 `--motion` 動態檢核）？
7. 大字與一般內文有無醜斷行？相鄰兩頁構圖有無變化（`series` 除外）？
8. **視覺指引檢核（`references/visual-guidance.md`）**：靜態三秒看懂主從與因果、動態同一時刻僅單一焦點無左右乒乓、聚光壓暗 390px 手機清晰且演畢 100% 回復？
9. 震撼頁前有鋪陳且具光暗對比嗎？brief 的地雷、限制、口徑與必放項目是否全部落實？
