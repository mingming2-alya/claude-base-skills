# 呈現規則：標題、重點、導航、震撼頁

整份簡報的視覺分工只有三層，每一層做一件事：

```
導航（章節列・目錄・頁籤）→ 告訴聽眾「在哪裡」   → 一致、安靜
一般重點（放大・突出色）  → 告訴聽眾「記住什麼」 → 每頁一處
震撼頁（獨立・淨空・停頓）→ 讓聽眾「有感覺」     → 全場 0–2 次，打破上面兩層
```

前兩層建立的秩序越穩定，第三層打破時就越有力。**震撼來自對比，對比需要先有秩序。**

## 標題

- 只說「這頁在講什麼」，像路標：「Q3 營收」「導入時程」「三個風險」。
- 不寫結論：不要寫「Q3 營收成長來自新客戶」。結論是重點，放在內容裡。
- 盡量 12 個中文字（或 6 個英文詞）以內。
- 為什麼：標題是給聽眾定位用的，講者在台上會說出結論，畫面負責把結論放大。

## 一般重點

- 每頁最多一個重點，用 `==重點文字==` 標記，build 會放大並套上突出色。
- 突出色**只**用在重點上，其他地方不准用突出色裝飾。這樣聽眾會學會「看到這個顏色 = 要記住」。
- 版型 `point` 就是「整頁只為一個重點服務」：重點放大置中，下面最多一行補充。
- 一頁塞不下就拆兩頁，不要縮字。
- 大字（封面標題、`point` 的重點句、震撼頁、結尾）**只會在標點後換行**。一個片語放不下一行時，build 會自動把字縮小（最多縮到 72%）；還是放不下才在片語內換行。所以長句請用逗號分成兩三個片語，或用換行指定斷點。

## 導航（由 build 自動產生，你只需要寫好 `chapters`）

| 情況 | build 自動做什麼 |
|---|---|
| 所有內容頁 | 頂端章節列：所有章節名稱，目前章節點亮 |
| 章節數 > 3，且每章平均 ≥ 2 頁 | 每章開始前插入**目錄點亮頁**：全部章節列出，目前章節亮、其他暗 |
| 章節數 > 3，但每章平均 < 2 頁 | 只在封面後插入**一頁目錄**；位置感交給常駐章節列（短簡報若每章插目錄，目錄頁會比內容還多） |
| 單章內容頁 > 2 | 章節列下方出現**頁籤**：該章每一頁一個小格，目前那格亮 |
| 封面、結尾、震撼頁 | 不顯示導航 |

頁籤文字預設用每頁的 `title`，可用 `tab` 欄位指定更短的名稱。

**不寫過場文字**：不要寫「接下來我們來看……」「了解背景後，讓我們進入方案」。如果你覺得需要這種句子，代表架構不夠清楚，回去調整架構，而不是加文字。

## 震撼頁（`type: shock`）

只留給兩種時刻：**情緒上的轉折**，或**刻意營造的衝擊**（像 Apple 的 One more thing）。一般重點用 `point` 版型就好，不要升級成震撼頁。

常見類型：反轉（「其實我們一直都想錯了」）、揭曉（鋪陳已久的答案）、數字衝擊、加碼（One more thing）、共鳴（一句話說中聽眾心裡的感受）。

規則：

- **必須有鋪陳**：前面至少要有一頁在建立預期，震撼頁才有東西可以打破。
  - 例外是**開場提問**（`role: opener`）：放在封面之後的第一頁，用一個問題讓全場停下來想，例如「你為什麼會被選中？」。它的鋪陳來自聽眾自己的經驗，不需要前面的頁面。
- **稀少**：全場 0–2 次（會議簡報通常 0 次）。兩個震撼頁之間至少隔 3 頁。
- **文字極短**：一句話，盡量 20 字以內。可以加一行很小的副句。
- build 會自動：隱藏所有導航、先切到全黑停頓、再讓文字浮現、整頁反轉成深底。

## 一頁總覽與附件

有兩種情境需要和一般「一頁一頁往下翻」的簡報不同的結構：

**一頁總覽（`layout: pillars`）**：整個架構濃縮在一頁，每章一欄。
- 適合：年度成果、策略總覽、作為大簡報的一章（`meta.format: section`：不需要封面、不顯示頁碼）。
- `headline` 是全頁主句，通常是一句平行的口號；`pillars` 每欄對應一章，依 chapters 的順序排列。
- 每欄可以有 `kicker`（小標）、`heading`、`sub`、`items`（最多 3 條）、`stats`（1–2 個關鍵數字），每欄最多一處 `==重點==`。
- 欄位高低會反映軸的方向：垂直軸（抽象層次、重要性）預設逐欄往下（`stagger: down`），讓版面本身說出「由上往下」。可以用 `stagger: up/none` 覆寫。

**可點入的附件（`appendix: true` ＋ `link`）**：
- 附件頁需要 `id`，不會出現在一般的翻頁順序裡。
- 總覽的某一欄、或任何一頁加上 `link: <附件 id>`，現場就能點進去；點返回鈕、按 Esc 或方向鍵都會回到原頁。
- 適合「台上只講總覽，被問到細節才點進去」的場合。lint 會檢查 link 的目標存在，也會提醒沒有被任何 link 指到的附件頁。

## 數字要有出處

震撼頁、`number` 版型，或任何作為論點的數字，都加上 `source`（例如「2026 年 9 月進展報告」）。build 會用小字顯示在頁面底部。為什麼：聽眾記住的往往是數字，數字一旦被質疑，整份簡報的可信度跟著倒。lint 會在含數字的震撼頁或大數字頁缺少出處時提醒。

## 有人際顧慮時：用「我們」提問代替陳述

brief 的人際顧慮為真時（`structure.sensitivity: true`），批評或問題不要直接陳述，改成以「我們」開頭的反思提問：

- 不要：「主管沒有把選育用留落實到課。」
- 改成：「我們選的是熟悉的人，還是最適合的人？」

為什麼：陳述句會讓聽眾覺得被指責，開始防衛；「我們」開頭的提問把講者也放進去，聽眾會開始自我檢視。數據也一樣：框成「系統卡在哪」，不要框成「誰做不好」。lint 會在出現「你們」時提醒。

## 數量與節奏

- 時長換算頁數：上台講大約每分鐘 0.4–1 頁。圖解密集、每頁要講比較久的說明型簡報偏低（真實案例：10 分鐘 4 頁內容），故事型、節奏快的偏高（真實案例：15 分鐘 9 頁）。
- 每章寫上預計分鐘數（`chapters[].minutes`）。總和加緩衝應等於時長，lint 會檢查。
- 章節 2–4 個；>4 個 lint 會報錯。理想是 3 個以內。
- 每章至少 1 頁內容。

## 品管清單（Step 5 看截圖時逐條檢查）

1. 只看章節名稱，能不能說出這份簡報要帶聽眾從哪裡到哪裡？
2. 每一頁三秒內看得出重點嗎？重點是不是全頁最醒目的東西？
3. 有沒有任何地方用了突出色卻不是重點？
4. 有沒有文字被切掉、擠在一起、小到後排看不清楚？大字有沒有斷在詞的中間（例如「營／收成長」）？有就加逗號或換行。
5. 有沒有過場文字或可以刪掉的說明句？
6. 震撼頁前面有鋪陳嗎？它看起來跟其他頁明顯不同嗎？
7. 每頁的字數，講者念完需要超過 30 秒嗎？超過就太多了。
8. 有沒有使用者在 brief「地雷」裡說不要的東西？
