# 視覺指引規格書（Visual Guidance Spec — Phase B.3）

> **核心信念**：動態不是為了讓畫面「都在動」，而是替觀眾拿著一把無形的手電筒——**靜態看懂主從與因果，動態跟上先後與轉折**。
>
> 本規格書定義 `deck-architect` 的**靜態動線骨架**與**動態視線導演原則**，與 `references/motion-system.md`（60fps 技術底盤）互為表裡：**前者管「觀眾眼睛怎麼走」，後者管「引擎怎麼順滑渲染」**。

---

## 一、第一性原理：為什麼「輪流淡入」不算視覺指引？

Phase B.2 實測診斷出五種常見「假指引」反模式，撰寫自由畫布頁時**一律禁止**：

| 反模式 | 觀眾體感 | Phase B.3 正解 |
|---|---|---|
| **1 秒一鍋端／過快難閱讀** | 全頁 4 拍在 1–2 秒內飛速演完，每拍只停 0.7 秒，觀眾連標題與數字都還沒讀完焦點就跳走了 | **每拍至少停留 1.3–1.8 秒**（多階段複雜頁總長 **3.2–4.6 秒**；封面／震撼頁 1.6–2.4 秒），同一時刻只有 **1 個主動視覺焦點** |
| **跨螢幕乒乓／四散跳躍** | 左上 → 右上 → 左下 → 右下交錯跳動，或看板先看左上再跳中下、最後看四散四角的小卡片 | **先空間分群、再單向流動**：如左欄「風險 ↓ 拍板」垂直閉環 → 右欄「健康總覽由高到低」群組；或先中心 → 左集群 → 右集群，**絕不回頭跳躍** |
| **手機隱形光環** | 用 10px 細微 `box-shadow` 標示重點，在 390px 手機縮放（~0.2×）後只剩 2px 幾乎看不見 | 採 **聚光＋非焦點壓暗**（配角退至 `opacity: 0.30–0.36`＋主角高反差描邊與 `≥ 20px` 舞台等效外光暈） |
| **孤點提前漂浮＋虛線拉扯** | 引導線還沒畫出，末端圓點就先懸在半空；或對 0 寬度 SVG `<line>` 做 `scaleX/scaleY` 導致縮放失效、虛線變形 | 嚴守 **「起點亮 → 線描出 → 終點綻放＋波紋 → 標註亮」**；實線用 SVG `<path data-draw>`、虛線直線用 HTML `data-wipe` |
| **只淡入結果、不演因果** | 數據改善頁或風險看板直接把「最終結果」靜靜淡入，看不出「改了什麼」或「哪張卡決定哪張卡」 | 用 **因果現場演變**（`data-transform-at` 舊態轉新態）與 **實體因果箭頭**（從風險卡正下方垂直指入拍板卡） |
| **移動球劫持視線（Motion Capture）** | 在多站時間軸上放一顆連續移動的亮球跨站滑行，人眼平滑追視反射會緊盯移動球，導致文字與插畫反而被忽略 | 採 **分段橋接軌線（Segmented Bridge Rail）**：每站停留閱讀期間畫面完全靜止，僅在切換到下一站的 300–400ms 過場瞬間才鋪出下一段連接軌線 |
| **轉場花招凌駕閱讀順序** | 試算頁讓右側結果數字先從前頁飛入，再跳回左側亮條件、再跳回右側長條；或產品頁讓左右兩欄同時搶跑 | **內容語意順序永遠高於轉場花招**：產品頁先看「輸入與做法」→ 再看「產出結果」→ 最後看「業務成效」；試算頁嚴守「左條件 → 箭頭 → 右結果」純單向流 |

## 二、四大靜態視覺動線原型（Static Eye-Flow Archetypes）

**鐵律：把所有動畫關掉（`?still=1`／列印 PDF）時，版面本身的構圖與連結符號依然能引導視線；且雙欄／儀表板頁面左右兩欄須對齊同一條底部基線（約 `y = 960–1014px`），不可在畫面下方留出失衡大塊空洞。** 撰寫每頁前，先從以下 4 種原型挑定主軸：

1. **分區因果流（Left Action Spine → Right Overview / Cause → Delta → Effect）**
   - **適用**：多店／多專案 Bento 進度看板、數據改善故事頁、前後對比。
   - **靜態骨架**：**同類必成群、不可四散四角**——例如看板頁採「左欄：唯一風險卡正對正下方拍板卡（同寬＋垂直中軸因果箭頭）」＋「右欄：其餘健康卡依總覽 → 高進度 → 低進度由上而下整齊排開」；讓眼睛走乾淨的「左上 ↓ 左下 → 右欄由上而下」單向路徑，零回頭、零四散。
   - **動態導演**：先定格「舊態／唯一風險」停留 **1.4–1.8 秒**讓觀眾完整讀完（配角壓暗退後）→ 演繹因果變化或垂直畫出因果箭頭指向解法 → 最後視線平移到右側完整群組，全頁回復 100% 平衡完稿。

2. **產品因果展開流（Input & Action → Product Result → Business Impact）**
   - **適用**：產品介面展示（Apple 平板／手機實景）、系統核心架構圖。
   - **靜態骨架**：裝置內部與外部標註必須**左右語意一致**——左半對左外標講「怎麼算／輸入與動作」，右半對右外標講「算出的結果與量化成效」，杜絕輸入與結果在左右兩側對角錯置。
   - **動態導演**：三拍獨立聚光、絕不左右同時搶跑——Stage 1 聚光「輸入與動作（含介面建議卡片逐張進場＋左側依據標註）」→ Stage 2 聚光「預報結果（核心指標＋走勢描線與端點波紋）」→ Stage 3 向右展開「最終量化業務成效」，全程由左向右單調推進。

3. **時間／流程分段流（Station Hold → Bridge Rail → Next Station）**
   - **適用**：AI 插畫場景（紙黏土三站）、時間軸、作業流程步驟。
   - **靜態骨架**：上方貫穿全站的水平時間細軌拆成各站之間的分段線，每站垂直向下對齊對應的實體物件，形成清楚的 T 型閱讀格線。
   - **動態導演**：**禁止連續奔跑的移動光球搶走視線！** 每一站依序獨立聚光（其餘站柔化壓暗）→ 虛線引導針由上往下掃落（`data-wipe="down"`）→ 觸及實體物件綻放波紋（`data-ripple`）→ **留足 0.7–0.9 秒完全靜止閱讀窗**讓觀眾看清標題與插畫 → 僅在換站瞬間用 350ms 鋪出前往下一站的短段連接軌線。

4. **控制→結果聯動流（Left Control → Causal Arrow → Right Live Output）**
   - **適用**：現場互動試算器（ROI／資源分配模擬）、參數推演頁。
   - **靜態骨架**：左操作（滑桿／情境按鈕＋精簡建置假設）與右結果（主 KPI＋對照長條）**頂部與底部雙邊對齊填滿畫布高度**（杜絕下方大塊空白），兩欄間以清晰方向箭頭建立「調左邊 → 變右邊」的心智模型。
   - **動態導演**：嚴守純因果由左至右順序——切頁採平順橫移（避免右側結果數字先於左側條件飛入）→ Stage 1 先聚光左側輸入條件並於閱讀該區時輕微提示 `⇄ 拖曳試算`（`data-nudge`）→ 畫出左→右因果箭頭 → Stage 2 一次亮起右側完整試算結果（主數字→次 KPI→對照長條由上而下）；一旦使用者提早拖動滑桿，立即解除聚光壓暗並即時亮顯聯動差額。

## 三、動態節奏與高反差五條鐵律

1. **一拍一主角、從容可讀＋閱讀期零干擾（Calm Reading Cadence & Still Hold）**
   - 人眼移焦＋閱讀一句 6–10 字短標與數字需要 **1.3–1.8 秒**；每拍焦點不得短於 1.2 秒，且動作完成後須保留 **0.6–0.9 秒完全靜止閱讀窗**（嚴禁旁邊還有持續移動光球或另一欄同時進場搶眼）。
   - 多階段敘事頁總演繹窗落在 **3.8–5.6 秒**；封面、震撼與附件頁收斂在 **1.6–2.4 秒**。
   - 搭配「永遠零鎖死可打斷」：想快轉的人隨時可一鍵切下一頁，想慢慢看的人也能從容讀完每一拍。
2. **高反差聚光＋三層明暗狀態（Focus Plan）**
   - 在 ≥3 區分階段頁面，使用 `<section data-focus-plan="1@0-2100, 2@2100-4150">` 搭配子元素 `data-focus="1|2|3"`：
     - **當拍焦點（`.focus-active`）**：`opacity: 1`、高反差邊框＋外光暈（舞台等效 `≥ 20px`，縮至 390px 手機仍清晰）＋微幅抬升 `scale(1.012)`（若為多卡大區塊群組或浮空文字，改加 `data-focus-style="clean"` 避免多餘外框）。
     - **已建立因果（`.focus-visited`）**：已演完的上一步維持 `opacity: 0.78–0.84`，保留因果脈絡。
     - **未出場背景（`.focus-dim`）**：退至 `opacity: 0.26–0.32`，徹底消除視覺雜訊。
     - **演繹完成／打斷／靜態模式／互動搶先操作**：所有 `.focus-*` 類別**自動清除**，全頁回到 100% 平衡清晰，絕不卡死半透明。
3. **線先到、點後綻、字再亮（Strict Connector Order）**
   - 實線箭頭／引導線：**必用 SVG `<path d="M 起點 L 終點" data-draw>`**，路徑座標必須順著視線行進方向書寫（例如由中央平板向左指，寫 `M 556,628 L 486,628`）。
   - 虛線直線／刪除線／時間軌：**必用 HTML 元素加 `data-wipe="down|right|left|up"`**（純 GPU `clip-path: inset(...)`），虛線節距零拉扯、無 SVG 零寬高邊界失效問題。
   - 錨點圓點與箭頭尖端：**必加 `data-pop`**，起點 `data-delay` 設在線開始前 `0–60ms`，終點與目標波紋（`data-ripple`）設在**線條抵達那一刻**（`lineDelay + lineDur - 40ms`）。
4. **保持既有翻頁互動模型，零額外點擊負擔**
   - 視覺指引是「自動演繹的注意力導演」，**不改變**方向鍵／點擊／手機滑動「一操作翻一頁」的直覺契約，不強迫講者多按好幾下才能翻頁。
   - 永遠支援**零鎖死可打斷**：演到一半按下一頁，所有計時器、焦點壓暗與狀態翻轉瞬間清理，零殘留。
5. **100% 確定性靜態終態（Still & Print Guarantee）**
   - HTML 原始 DOM 預設即為**最終正確閱讀狀態**（如 9 綠 15 省下、完整對比、全卡 100% 不透明）；「演變前狀態」（`.pre-transform`）與「焦點壓暗」（`.focus-dim`）僅在動態播放進頁瞬間由 `runtime.js` 掛上並按時移除。
   - 如此可從根源保證 `?still=1`、`B` 鍵省電、`prefers-reduced-motion`、`@media print` 與 `check.mjs` 像素 WCAG 檢查永遠測到最乾淨的最終完稿。

## 四、底盤視覺指引原語速查表（`shell.css` + `runtime.js` v4.3）

| 屬性／語法 | 用途與視覺效果 | 關鍵參數 | 靜態／列印行為 |
|---|---|---|---|
| `data-focus-plan="1@0-1000, 2@1000-1800"` ＋ `data-focus="1\|2\|3"` | **聚光＋非焦點壓暗排程**：在指定時間窗高反差點亮當前拍，壓暗未出場配角（`0.32`），已演完留為脈絡（`0.82`），結束自動全頁復原 `1.0` | 掛在 `<section class="slide">`；卡片設 `--spot-border`、`--spot-glow` | 完全停用，全頁 `opacity: 1` |
| `data-spotlight` | **高反差單次聚光框**（升級為雙層亮邊＋22px 外光暈，390px 手機亦清晰） | `data-delay`、`--spot-border`、`--spot-glow` | 不閃動，維持正常邊框 |
| `data-transform-at="780"` | **因果現場演變**：進頁瞬間先套 `.pre-transform` 呈現舊態，於指定毫秒移除並切換為最終新態（加 `.transforming` 700ms 供過場動畫） | 毫秒數（相對於轉場基準） | 直接呈現最終態（無 `.pre-transform`） |
| `data-draw` / `data-draw="ring"` | **SVG 實線路徑／圓環真描繪**（`pathLength="1"`，順座標方向繪出） | `data-delay`、`data-dur` | 直接完整繪出 |
| `data-wipe="right\|left\|down\|up"` | **純 GPU `clip-path` 方向揭露**（專治虛線引導針、時間軌、斜刪線、細線，零變形） | `data-delay`、`data-dur` | 直接完全展開 |
| `data-pop` | **端點圓點／箭頭／徽章精準綻放**（縮放 0.25→1，與引導線起止時刻精準銜接） | `data-delay`、`data-dur` | 直接正常顯示 |
| `data-ripple` | **目標點雙圈擴散波紋**（純 HTML，釘住 3D 插畫物件或折線終點） | `data-delay`、`--ripple-color` | 自動隱藏（不干擾靜態版面） |
| `data-travel="x\|y"` | **單段短距橋接光珠**（僅用於兩節點間短距過場，禁止跨多站連續滑行以免劫持閱讀視線） | `data-travel-dist`（px）、`data-delay`、`data-dur` | 自動隱藏 |
| `data-nudge="x"` | **互動控制微動暗示**（進場後單次輕微左右點頭，無字提示滑桿可拖曳） | `data-delay` | 自動停用 |
| `data-beat="1\|2\|3\|4"` ＋ `data-from` | **語意分拍方向進場**（搭配 `data-delay` 精準對齊） | `left\|right\|up\|down\|none` | 直接正常顯示 |

## 五、Step 5 視覺指引品管清單（人工＋`check.mjs --motion`）

製作完成後，除原本的靜態像素 WCAG 檢查外，逐頁確認 6 題：

1. **三秒靜態動線**：關掉動畫（`?still=1`）看截圖，視線是否仍自然從主角流向結論／拍板點？
2. **零同時混戰**：動態進場時，同一時刻是否只有 1 個主焦點在移動，沒有左右跨螢幕乒乓？
3. **手機 390px 可辨識度**：縮成手機寬度觀看，聚光壓暗、因果演變與引導箭頭是否依然一眼看得見？
4. **線點時序零破綻**：是否有引導線末端圓點在線條還沒到達前就先漂浮？虛線是否保持銳利無拉扯？
5. **零殘留復原**：整頁動畫演完（以及快按方向鍵打斷後），所有 `.focus-dim`、`.focus-active`、`.pre-transform` 是否 100% 歸零恢復清晰？（`check.mjs --motion` 自動實測）
6. **去小字不回潮**：所有視覺指引皆靠光影、反差、線條、波紋與微動傳達，絕不為了「引導」而加回第 3 層冗餘解說小字（嚴守原則 #26）。
