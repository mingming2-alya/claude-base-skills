# 架構：把聽眾從起點帶到終點

## 核心模型

> **架構，是把聽眾從「他現在在哪」帶到「你希望他在哪」的路徑。**
> **路徑沿著一條聽眾直覺就懂的軸，往單一方向走。**

| 元素 | 意思 | 從哪來 |
|---|---|---|
| 起點 | 聽眾現在知道什麼、在意什麼 | Grill 的「對象」 |
| 終點 | 聽完後要相信什麼、做什麼 | Grill 的「目的」 |
| 軸 | 起點和終點差在哪個維度上 | 你推導 |
| 方向 | 從起點那端往終點那端走 | 你推導 |
| 停靠點 | 章節：軸上的 2–4 個點，用這次內容自己的話命名 | 你推導，使用者確認 |

為什麼要單一方向：聽眾一旦知道你沿著什麼在走，就能預測下一章。**能預測就不需要過場文字**，也不會迷路。來回跳躍或中途換軸，聽眾每換一章都得重新理解你的邏輯。

## 軸的種類

軸的種類很少，組合起來卻沒有上限。不要把下面的例子當選單；它們只是同一個原理的示範。

| 軸 (`axis`) | 兩端 | 性質 | 換章運鏡 | 例子 |
|---|---|---|---|---|
| `time` 時間 | 過去 ↔ 未來 | 中性 | 水平 | 年初的困境 → 轉型的半年 → 明年的方向 |
| `process` 流程 | 上游 ↔ 下游 | 中性 | 水平 | 產品 → 業務 → 客服 |
| `causal` 因果 | 原因 ↔ 結果 | 中性 | 水平 | 背景 → 方案 → 成效 → Takeaway |
| `abstraction` 抽象層次 | 理念 ↔ 執行 | 中性 | 垂直 | Why → What → How；架構 → 分工 → 細節 → 回報 |
| `importance` 重要性 | 結論 ↔ 細節 | **價值** | 垂直 | Top Down（結論先）／Bottom Up（細節先） |
| `scale` 尺度 | 整體 ↔ 局部 | 中性 | 縮放 | 產業 → 公司 → 團隊（大到小） |
| `distance` 距離 | 遠 ↔ 近 | 中性 | 縮放 | 全球趨勢 → 台灣市場 → 你的店 |
| `intensity` 強度 | 弱 ↔ 強 | **價值** | 水平 | 最小影響 → 最大影響 |

- **價值軸**隱含評價或排名（誰比較好、什麼比較嚴重）。
- **中性軸**只是陳述事實（先後、上下游、遠近）。
- 若軸都不適合，可以用 `custom` 並在 `axis_note` 說明兩端，但先確認它真的是一條聽眾直覺能懂的線。

## 怎麼推導

1. **先看終點和起點差在哪。**
   - 老闆只在意結論、時間很少 → 差在「重要性」→ `importance`，結論先（Top Down）
   - 學生不懂為什麼要學 → 差在「抽象層次」→ `abstraction`，從 Why 開始
   - 客戶覺得事不關己 → 差在「距離」→ `distance`，從遠講到他身上
   - 回顧一年 → 差在「時間」→ `time`
2. **方向從起點那端出發。** 同一條軸，聽眾起點不同，方向就不同（Top Down vs Bottom Up）。
3. **有人際顧慮時，選中性軸。** 例：三個部門的成果，依成績排序等於公開排名；依業務流程排序就不會得罪人。
4. **停靠點 2–4 個。** 超過 4 個代表軸切得太細，合併相鄰的點；只有 1 個代表那不是架構。
5. **命名用這次內容的話，而且要平行**：結構、長度、詞性一致。
   - 好：「年初的困境 / 轉型的半年 / 明年的方向」
   - 不好：「背景 / 我們做了哪些努力 / Future」（長度、詞性、語言都不一致）

## 主體之外：序幕、轉折點、尾聲

「單一軸、單一方向」管的是**章節主體**。真實的演講還有三種不屬於任何一條軸的元素：

| 元素 | 位置 | 作用 | 例子 |
|---|---|---|---|
| 序幕 | 第一章之前，或第一章的第一頁 | 用一個問題、畫面或事實先抓住聽眾 | 「你為什麼會被選中？」 |
| 轉折點 | 某一章內部 | 拋出「做到這些就夠了嗎？」，用**故事**回答，再帶出下一步 | 先呈現現況與已做的事，問「這樣就能持續強大嗎？」，再講故事 |
| 尾聲 | 最後 | 一句結語收束整份簡報，通常回扣序幕或故事 | 「打造一代比一代更強的團隊」 |

**故事不一定放在開場。** 故事最有力的位置，往往是轉折點：它回答一個聽眾剛被勾起的問題，而不是一開始就講一個還沒有問題可回答的比喻。提出架構候選時，說明故事要放在序幕還是轉折點，以及為什麼。

## 兩個層次

| 層次 | 結構 | 導航 |
|---|---|---|
| 架構層（整份簡報） | 永遠是一條路徑，不可以是並列 | 章節列、目錄點亮頁 |
| 內容層（章節裡面） | 可以並列（三個優勢、三個風險），但仍要有排序依據 | 頁籤 |

使用者的經驗：「三個優勢」不會是整份簡報的架構，它只會是「解法」那一章**裡面**的內容。如果你發現最上層是並列的，往上找一層：這些並列項目要把聽眾帶去哪裡？那才是架構。

## 使用者已有框架時

使用者或團隊常常已經有一版框架。**它一定要成為候選之一**，不要只提你自己推導的新架構。

- 先判斷它沿的是哪條軸。例如「現況 → 我們的努力 → 共勉」是因果軸（問題 → 回應 → 期許）。
- 如果它沿著同一條軸、單一方向，原樣列為候選 A，再提 1–2 個真的不同的替代方案。
- 如果它混了兩條軸或來回跳，指出是哪裡，並提出最小修改版本當候選。
- 為什麼：使用者的框架通常包含你在 Grill 裡問不到的脈絡，例如團隊共識、主管偏好。第一次真實比對時，Claude 沒列入團隊框架，結果使用者選了別的候選，最後又改回接近原框架的版本。

## 提出候選的格式

給使用者 2–3 個候選，每個這樣寫：

```
A｜沿時間，過去 → 未來（中性軸）
   年初的困境 → 轉型的半年 → 明年的方向
   適合原因：聽眾知道結果但不知道過程，用時間帶他們重走一次，最後落在明年要的支持。
   序幕：一個年初的真實場景　轉折：在「轉型的半年」用一位客戶的故事　尾聲：回到序幕的場景
   時間：3 分／6 分／4 分（共 13 分，緩衝 2 分）
```

候選之間要真的不同（不同的軸，或同軸不同方向），不要給三個換湯不換藥的版本。
